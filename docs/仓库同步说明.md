## 3. 历史元数据与可复现性

`runs/`、`evaluations/` 及各实验目录中的 JSON/JSONL 提供参数、预算、来源和预测证据。即使文件名含 checkpoint 或 adapter，也可能只有配置和 hash；不能将它们当作完整可加载模型。manifest 记录的服务器绝对路径、权重 SHA、归档名和文件大小是历史资产身份，不表示相应文件已附带。

冻结运行时与身份清单用于追溯原结果。本次更名和路径调整不改写历史源码、run、来源清单及其哈希。新实验应调整 `/root/autodl-tmp/...` 等资产路径、读取相应协议、另建输出目录，并为新输入与实现记录新的身份。旧 VisA 划分实现按绝对路径字符串取 MD5，迁移数据根后应保留冻结 manifest 或严格映射原规则。

完整 GPU 复现需另备数据、底座、teacher、对应 seed 桥接及 adapter 等；仅有代码与预测可以进行 CPU 指标复算。服务器历史 fresh 核验、本机保存预测复算和本次重新跑模型是不同范围，应分别表述。现有训练未保存完整 optimizer/scheduler 状态，不能精确恢复中断训练轨迹。

## 4. 同步与认证边界

提交时只纳入交付清单和已核对的根级配置，检查实际路径与差异；本地的无关修改、数据、模型、认证与会话不得因目录合并而自动入库。Git 提交身份沿用用户指定邮箱 `qiaohfcs@163.com`。远端仓库名称和默认分支内容，应通过 GitHub 仓库信息、提交 SHA 与完整目录树核验。

SSH 辅助入口如 `industrial_vlm/ops/remote.py` 通过命令参数或环境变量配置目标；认证交给 SSH 与系统凭据管理。仓库不提供服务器口令、密钥或原始认证对话。
