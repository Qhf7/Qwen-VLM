# 跨零件分割：DINO、语言锚点与历史对齐探索

## ① 动机：见过腰果缺口，能否找到另一种零件的划痕

在同一产品上学习与在未见类别上泛化，是两个问题。跨零件路线希望从部分零件学到可迁移的异常定位能力，再到训练中没有出现的产品类别上输出像素图。

**教学例子**：训练只见 A 类螺丝和 B 类夹子，测试 C 类接口的刮痕。模型不能仅靠记住“这个零件长这样”完成任务。冻结预训练视觉特征、只训练分割头，可以降低需要学习的参数，但跨类别泛化仍必须通过隔离测试来验证。

“未见类别”不是“未见图片”的同义词；同一零件的另一视角也不是完全独立的新物体。数据协议是本路线的重要工作。

## ② 架构：冻结视觉主干，训练像素解码器

```text
RGB [B,3,448,448]
 → 冻结 DINOv2-B/14
 → 第 3/6/9/12 层 patch 特征，各 [B,768,32,32]
 → 四个 1×1 Conv，各投影成 [B,256,32,32]
 → cat 通道：[B,1024,32,32]
 → 3×3 Conv＋GroupNorm＋GELU：1024→256→128
 → bilinear 上采样：[B,128,448,448]
 → 1×1 Conv head：[B,1,448,448]
 → squeeze：[B,448,448] logits
 → sigmoid：逐像素异常概率
```

代码：[train_seg.py · DinoFeatures.forward](../../seg_cross_part/train_seg.py#L183)；[train_seg.py · SegDecoder.forward](../../seg_cross_part/train_seg.py#L209)；[train_seg.py · SegModel.forward](../../seg_cross_part/train_seg.py#L229)。

### backbone、decoder、head 分别是什么

| 术语 | 在此处的模块 | 干什么 |
|---|---|---|
| backbone / 主干 | 冻结 DINOv2 | 把 RGB 转成多层视觉表示 |
| decoder / 解码器 | SegDecoder | 融合特征，恢复到目标空间分辨率 |
| head / 输出头 | 最后的 1 通道卷积 | 每个位置输出一个实数 logit |
| logit | sigmoid 之前的数 | 0 对应概率 0.5，2 对应约 0.881 |
| feature map | [通道,高,宽] 数组 | 每个位置含一组特征，不等于 RGB 图 |

这里“解码”是恢复密集输出，与语言模型逐 token 解码是不同操作。上采样不会凭空恢复已丢失的精细信息；32×32 特征最终输出 448²，不保证能分清每条亚 patch 细划痕。

### 1×1、3×3 卷积、GroupNorm 与 GELU

- **1×1 卷积**只混合当前位置的通道。768→256 相当于每个空间位置共享一个线性投影，含偏置时参数为 768×256+256=196,864。
- **3×3 卷积**额外整合邻近位置，扩大局部感受野；padding=1 保持宽高。
- **GroupNorm**把通道分成组归一化；当前使用 8 组，通常比依赖 batch 统计的 BatchNorm 更适合很小 batch。它不等于输入的 ImageNet 像素标准化。
- **GELU**是平滑非线性，使多层组合不退化成单个线性变换。
- **双线性插值**按邻域加权补点；nearest 选择邻近离散值。图像/连续特征可以插值，类别 mask 通常使用 nearest。

`StubFeatures` 用随机卷积模拟相同接口，只适合冒烟检查：验证张量能通、循环能运行。它的结果不能当作预训练 DINO 性能。

代码：[train_seg.py · SegDecoder.__init__](../../seg_cross_part/train_seg.py#L199)；[train_seg.py · StubFeatures](../../seg_cross_part/train_seg.py#L156)。

## ③ 训练：为什么不只算像素准确率

小缺陷可能只占图像 0.1%。若全部输出正常，像素准确率可达 99.9%，但所有缺陷都漏掉。该路线组合 Focal 与 Dice：

```text
p = sigmoid(logits)
pₜ = p × y + (1−p) × (1−y)
CE = −y log p − (1−y) log(1−p)
L_Focal = mean[(1−pₜ)² × CE]
L_Dice = 1 − (2Σpy + ε) / (Σp + Σy + ε)
L = 0.5 L_Focal + 0.5 L_Dice
```

| 符号 | 含义 |
|---|---|
| p | 每个像素预测为异常的数，0–1 |
| y | GT 像素，正常 0、异常 1 |
| pₜ | 模型给真实类别的概率 |
| gamma=2 | 降低容易像素的贡献 |
| ε=1e−6 | 避免分母为零 |

**教学手算**：两个像素 GT=[1,0]、p=[0.8,0.2]。两者给真实类别的概率均为 0.8，CE≈0.2231，Focal≈0.2²×0.2231=0.00893。交集软计数为 0.8，预测之和 1、GT 之和 1，Dice loss≈1−1.6/2=0.2，总损失≈0.10446。

若一个异常像素只预测 0.2，则它的 Focal≈0.8²×1.609=1.03，远高于容易像素。Dice 直接关心前景整体重叠，但当前 `sum()` 在整个 batch 上聚合，面积大的图会影响更大；它不是逐图 Dice 后简单平均。

`binary_cross_entropy_with_logits` 将 sigmoid 和 BCE 合并得更数值稳定。训练不能先把概率 >0.5 变成硬 0/1 再算损失，因为硬阈值无法提供有效连续梯度。

代码：[train_seg.py · focal_dice](../../seg_cross_part/train_seg.py#L246)；训练入口 [train_seg.py · train](../../seg_cross_part/train_seg.py#L293)。

## ④ 数据：五视角、近重复与划分

历史数据地基包括 Real-IAD 24 类、5,971 个采集组、29,855 张视角图、4,231 个近重复视觉组。数字来自已有 manifest 统计与[项目说明](../项目说明.md)，本次没有重新打开全部原图核验。

| 字段 | 含义 | 为什么要有 |
|---|---|---|
| image_path | 一张视角图相对路径 | 唯一定位输入 |
| mask_path / mask_valid | 掩码路径、是否有有效掩码 | 正常图通常配全零 GT |
| class_name | 产品类别 | 未见类别划分、逐类汇总 |
| view_label | 当前视角是否异常 | 不等同于采集组是否存在某个异常视角 |
| group_path | 同一采集对象的五视角组 | 采集相关性与组级统计 |
| visual_group_id | 近重复视觉组 | 让相似来源留在同一 split |

**教学例子**：同一零件 C1 视角看见刮痕，C5 没看见。若把采集组的异常标签直接赋给每个视角，会制造标签噪声；若 C1 训练、C2 测试，又可能因外观相近泄漏。项目划分强调按视觉组整体分配；bootstrap 还要说明采用的是哪一种组。

协议文件见 [Protocol B](../../seg_cross_part/protocols/protocol_b_seen_category.yaml)、[Protocol C](../../seg_cross_part/protocols/protocol_c_unseen_category.yaml)。历史 Protocol A/B/C 的字段语义以配置和 manifest 为准：总体分组划分、已见类别内划分、整类留出不能混称同一种泛化。C 使用四折，每折 18 类训练、6 类测试，按固定类别顺序轮换，不能叫语义均衡随机分层。

### 一张图如何变成训练样本

`SegDataset.__getitem__` 返回：

```text
归一化 RGB tensor、二值 GT、image_path、class_name、view_label
```

训练随机裁剪和水平翻转使用**同一组几何参数**同时处理 RGB 和 mask；颜色标准化仅处理 RGB。验证只缩放。RGB 用 bilinear，mask 用 nearest。

**教学例子**：原图右上角缺陷经过水平翻转应在左上角。若只翻图不翻 GT，就让模型看着左上划痕却被要求预测右上，直接破坏监督。

当前 Real-IAD 路径按 mask>127 二值化；原生 VisA 则将所有非零索引视为异常。真实腰果 mask 值包含 8，若把它直接送进 >127 规则会全部变成背景。因此不同数据集 loader 不能无条件互换。

项目还写了亮块图与对应 mask 的几何对齐自检：重复变换后 IoU 至少 0.90；边缘插值带来少量差异。它检查几何变换，不证明真实数据集的所有标注正确。

代码：[train_seg.py · SegDataset._load_mask_pil](../../seg_cross_part/train_seg.py#L72)；[train_seg.py · SegDataset._geom](../../seg_cross_part/train_seg.py#L79)；[train_seg.py · check_alignment](../../seg_cross_part/train_seg.py#L118)。

## ⑤ 可选语言支路：文本锚点不是文本生成

### CLIP 文字向量

`build_anchors` 用冻结 CLIP 文本塔编码正常/异常提示，取 EOS 位置隐藏表示，再 L2 归一化，得到 [K,d] 锚点。这里实际调用 CLIPTextModel 的隐藏表示路径；不要把它笼统等同于所有 CLIP API 返回的带投影图文 embedding。

DINO 四层拼接 [B,3072,32,32]，通过可训练卷积投影到文本锚点维度 d。归一化后，与每个锚点算余弦相似度并乘 10。

```text
similarity[b,k,h,w] = 10 × cosine(z[b,:,h,w], anchor[k,:])
normal = logsumexp(正常锚点分数)
anomaly = logsumexp(异常锚点分数)
aux_logit = anomaly − normal
最终 logit = decoder_logit + aux_logit
```

`logsumexp(a) = log Σ exp(a)`，是稳定聚合多个候选的操作。**示意**：正常分数 [1,1] 得 1+ln2≈1.693，异常分数 [2,2] 得 2.693，差为 1。若两组锚点数不等，这个求和还带数量效应，应检查提示配比，不能只看最高分。

代码：[a2_language.py · build_anchors](../../seg_cross_part/a2_language.py#L46)；[a2_language.py · LanguageBranch._sim](../../seg_cross_part/a2_language.py#L104)；[a2_language.py · LanguageBranch.forward](../../seg_cross_part/a2_language.py#L121)。

### 随机锚点、打乱锚点是在排除什么

加入分支后提升，可能来自更多参数，也可能来自真实语义。随机方向锚点与正常/异常提示打乱可以作为对照，帮助区分容量、分组和语义的作用。

不过 `random` 模式不实际编码 prompts，`shuffle=True` 对这种模式并不会像 CLIP 分支那样改变文本向量语义。因此对照要检查具体输入是否变化，不能只相信实验名称。随机方向也不是“无分支”；可训练投影仍有容量。

### gate 写了，不代表训练已调用

`LanguageBranch.modulate` 定义了特征乘法门控 `f′=f×(1+gate)`；sigmoid gate 在 0–1，使缩放在 1–2。它有能力构造文本上下文调制，但当前 `SegModel.forward` 调用的是 `self.lang(f,...)`，然后 **logits+aux**，没有调用 `modulate`。

因此本次源码证据支持“实现了 additive 语言分支；另有 gate 函数定义”，不能直接写成“主训练已用语言门控逐位置改写 DINO 特征”。某些旧文档还写 A2 未实现，与后续源码版本不一致，应以具体运行配置和快照为依据。

代码：[a2_language.py · LanguageBranch.modulate](../../seg_cross_part/a2_language.py#L110)；[train_seg.py · SegModel.forward](../../seg_cross_part/train_seg.py#L229)。

## ⑥ 两种历史探索，分别走一遍

### A3：额外缓存视觉特征融合

`VLMFeatStore` 用 mmap 读取 .npy，用 parquet 索引找对应 image_path；每张缓存是 28×28×512。DINO 四路加缓存一路，分别投影为 256 通道，拼成 1280 通道，再卷积、上采样输出分割图。

**示意 B=1**：

```text
4×[1,768,32,32] → 4×[1,256,32,32]
缓存 [1,512,28,28] → resize32×32 → [1,256,32,32]
cat → [1,1280,32,32] → decoder → [1,448,448]
```

缓存提取还有固定随机投影 1152→512。这是降维操作，并没有因此学出针对缺陷的语义对齐。

静态阅读发现两项需要复用前检查的问题：

1. `FusionDataset` 让底层 RGB/mask 随机裁剪、翻转，但按路径取出的缓存空间网格没有同步这些几何变换。训练时可能出现两路位置错位；需对照实际训练参数和缓存坐标系核实。
2. 找不到缓存时用零向量代替。这样能继续前向，但必须统计缺失率，否则无法确定实验真正用了多少额外信息。

以上是代码检查项，本次没有重新跑训练验证，也没有修改历史实现。

代码：[train_a3.py · VLMFeatStore](../../seg_cross_part/train_a3.py#L32)；[train_a3.py · FusionDataset.__getitem__](../../seg_cross_part/train_a3.py#L55)；[train_a3.py · FusionDecoder.forward](../../seg_cross_part/train_a3.py#L76)；[extract_vlm_feats.py · build_projection](../../seg_cross_part/extract_vlm_feats.py#L33)。

### DINO→LLM：把视觉 patch 变成 64 个软 token

`align_dino_llm.py` 的 projector 用两次 stride=2 卷积，把 32×32 空间降到 16×16、8×8，维度 768→1024→4096，再展平成 [B,64,4096]。拼到文字 embedding 前，送进冻结 Qwen 语言模块。

它使用的是外接视觉 token，不能当成原生 Qwen 视觉输入。维度4096只保证能拼接，不保证语义已经对齐。生成循环每步拼接完整历史、重新前向；它没有采用评测桥接版本的 KV cache 方式。

**静态实现疑点**：训练循环遍历 batch 每个答案时，拼接的是 `vis[:1]`，而不是对应样本索引。batch=2 时，第二个答案也可能配到第一张图的视觉表示。`al.build` 的 dino_feats 参数当前不负责补偿这一点。复用前需检查并在独立修复任务中验证；这不构成本次重跑结果。

代码：[align_dino_llm.py · Projector.forward](../../seg_cross_part/align_dino_llm.py#L45)；[align_dino_llm.py · Aligner.generate](../../seg_cross_part/align_dino_llm.py#L78)；[align_dino_llm.py · main](../../seg_cross_part/align_dino_llm.py#L103)。

### 二选一任务与单图异常任务

历史 `eval_pair_big.py` 把两张图并排输入，其中一张正常、一张异常，要求选 1 或 2。答案相对位置随机化，随机基准为 50%。

已保存 1,200 组结果为 79.25%（951/1200）。它支持这批配对图像存在相对判别信号；对另一批零样本的 75% 所算 +4.25 点，非配对比较 p=0.124，不能证明 SFT 稳定增益。样本有放回构造、置信区间没有完整覆盖重复视角的组相关性；也不能从两批不同分辨率/样本推断“与分辨率无关”。

历史 66.7% 的单图判断后来被查明相当于偏向恒答，不应继续当作已学会异常检测的正向证据。详见[阅读核对](../阅读核对_20261023/AnomalyGPT与本项目.md)、[实验台账](../实验进度与版本记录.md)。


### WinCLIP思路基线：窗口、文本集成与正常参考记忆

本项目还实现了`winclip_b2.py`。它沿用WinCLIP的窗口与文本原型思路，但将视觉参考关联换成DINOv2，使用的CLIP型号、提示和窗口步长也有差别，应称为**改写基线**。

**文本集成 / prompt ensemble**：把状态词和模板组合，例如“normal object”“flawless object”放进“a photo of a ...”，编码、归一化，分别平均为正常/异常原型。CLIP这一支使用text_projection，与前面的A2隐藏空间锚点路径有区别。

**窗口CLS**：整图可能忽视小缺陷，所以在24×24 patch格上取2×2、3×3局部窗口，每个窗口带CLS送入CLIP编码器；比较窗口与两个文本原型。这里2×2指patch数，不是2像素；对应基础patch尺度约28×28输入像素，但模型特征还受位置处理和上下文影响。

多个窗口覆盖同一位置时使用**调和平均**：

```text
H(a,b) = 2 / (1/a + 1/b)
教学：a=0.2、b=0.8，H=0.32；算术平均为0.5
```

调和平均更受较小值影响；不是取最大值，也不是训练出来的权重。当前文件另提供mean/max/ref等融合模式，配置不同的数字不能混称相同基线。

代码：[winclip_b2.py · ClipWindowScorer.text_prototypes](../../seg_cross_part/winclip_b2.py#L126)；[winclip_b2.py · ClipWindowScorer.maps](../../seg_cross_part/winclip_b2.py#L162)；[winclip_b2.py · _harmonic](../../seg_cross_part/winclip_b2.py#L104)。

**正常参考库 / memory bank**：K张正常图，每张1024个DINO patch，展成[K×1024,768]单位特征。对待检patch q，找参考库中余弦最相似的一个：

```text
s(q) = 0.5 × (1 − maxₘ cosine(q,m))
```

**教学例子**：K=4，共4096个参考向量。待检patch与三个代表性参考相似度为[0.95,0.5,0.2]，取最大0.95，异常分数0.025；另一个patch最高只有0.3，分数0.35，说明它不像现有正常参考。这个分数表达“不像参考”，不保证所有正常变化都已被覆盖。

这里的K指**正常参考图片数**，不是kNN中取k个最近邻的k；本实现对每个query取1个最佳匹配。无需反向传播也能利用目标类别样本，因此“不训练权重”不等于“zero-shot”。

代码：[winclip_b2.py · DinoRef.build_memory](../../seg_cross_part/winclip_b2.py#L226)；[winclip_b2.py · DinoRef.score](../../seg_cross_part/winclip_b2.py#L231)。

协议细节也要读`main`：当前从所评split的正常图挑参考，并排除这些参考图本身的评分；目标类别正常先验已被使用。defect模式还从该评测子集的`defect_norm`整理缺陷词，属于额外的缺陷词表信息。若要宣称部署可用的zero-shot协议，须事先冻结可用词表，不能临时根据测试异常标签生成。

**边界格子的具体例子**：`stride=2` 时，3×3窗口起点为0、2、4……20；最后一扇窗覆盖到第22行/列，所以24×24网格最末行和最末列没有被这个尺度覆盖。`_agg`把这些位置填成1.0。此分支输出的是异常概率，高值表示更异常；代码注释却称填充值代表“非异常”。最终融合还会经过其他尺度，因此不能据此断言整张图的最终输出，但这是需要单独核查并做边界测试的实现疑点。

代码：[winclip_b2.py · ClipWindowScorer._agg](../../seg_cross_part/winclip_b2.py#L194)；[winclip_b2.py · main](../../seg_cross_part/winclip_b2.py#L241)。

### 历史实验读数：少样本视觉参考占主要作用

已有 Protocol C fold 0 结果显示，4-shot 的“正常参考记忆”路线分数较强，而加入通用 CLIP 语言窗图的提升很小。下表使用**六个未见产品类别的类宏平均 AUPRO@0.3**；B0 不取参考图，B1/B2 每类从该评测 split 抽4张正常支持图，并从评分中排除这24张图。它们是历史测试 split 上的探索结果，不是本轮重新推理，也不能与本章四折总结果或原生 Qwen 的图像级 AUROC直接比较。

这组结果支持一个有限结论：B0 到 B1 的大幅差距与目标类正常参考信息相伴；在 B1 上加通用语言窗图，类宏点估计只多约0.62个百分点。具体缺陷提示使 B2 明显变差；换成 max 后回升约5.23个百分点（0.6413−0.5890），但仍低于 B1。它说明融合规则会影响结果，也说明“提示更具体”不保证定位更好。它没有证明所有 CLIP 语言支路都无效。

统计口径需特别谨慎：三份通用词结果 JSON 的 `macro.apro_0.3` 分别约为 B0=0.30895、B1=0.76165、B2=0.76784；因此 JSON 类宏点估计差为 +0.00619。实验台账另写 B2−B1 配对 bootstrap Δ=+0.0040，同时给出 `[-0.0064,-0.0019]` 的区间并称“不显著”，区间符号与点估计方向不一致，且区间不含0。此处只报告各结果文件直接保存的类宏点估计；没有复用该 bootstrap 显著性说法，若要报告推断结论，应从原始逐组统计重新核对配对单位、差值方向和置信区间。

`defect` 变体还从同一评测子集的异常行读取 `defect_norm`，所以它使用了测试侧缺陷类型元数据。它是标签知情的诊断消融，不能包装成严格 zero-shot 或无测试信息的部署评测。结果入口：[B0 通用词](../results/B0_winclip_zeroshot_fold0.json)、[B1 纯视觉参考](../results/B1_dino_ref_k4_fold0.json)、[B2 通用词融合](../results/B2_winclip_dino_k4_fold0.json)、[缺陷词与 max 融合记录](../实验进度与版本记录.md#L387)。


## ⑦ 这条路线留下什么

主要积累是按来源分组的数据协议、冻结视觉特征分割基线、像素评测与组 bootstrap、语义对照设计。已有汇总中，四折未见类别 AUPRO@0.3 为 65.87%±5.63%；这里的 ± 是折间变化，不能与原生单种子120图 AUROC直接比较，也不能当作三种子标准差。

本章的关键代码阅读顺序：`SegDataset` → `DinoFeatures` → `SegDecoder` → `focal_dice` → `SegModel` → `LanguageBranch` → `PixelEvaluator`。先把不带语言的闭环弄懂，再理解额外分支。
