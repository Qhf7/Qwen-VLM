# ① 动机与②架构：用检查零件的例子建立概念

## 1. 这个任务到底要什么

设想一张螺丝照片。工厂首先要知道能否放行；返修人员想知道划痕在哪；研究人员还可能要求每个缺陷像素的掩码。

| 名称 | 人话解释 | 示意输出 | 本项目代码 |
|---|---|---|---|
| 图像级异常检测 | 整张图是否有缺陷 | `true` 或分数 0.9 | [score.py · _score_image](../../industrial_vlm/src/industrial_vlm/score.py#L226) |
| 区域定位 / grounding | 缺陷大概在哪里 | `[100,200,300,400]` | [data.py · _mask_info](../../industrial_vlm/src/industrial_vlm/data.py#L80) |
| 语义分割 | 每个像素是不是缺陷 | `H×W` 的 0/1 或概率数组 | [train_seg.py · SegModel](../../seg_cross_part/train_seg.py#L221) |
| 语言回答 | 用可读文本回答问题 | `Yes, ...` 或 JSON | [infer.py · main](../../industrial_vlm/src/industrial_vlm/infer.py#L12) |

项目的实际训练/评估数据主要是 Real-IAD 和 VisA，不是这里虚构的螺丝样本。“异常”指对应数据标注定义的缺陷；不能把所有不常见外观都自动视为不合格。

## 2. 先把数组、张量与图像弄清楚

**张量 tensor** 是多维数值表。图片原始像素常记作 `[H,W,3]`；PyTorch 图像批次常记作 `[B,3,H,W]`。B 是 batch 内样本数，3 是 RGB 通道。

**示意**：一批 2 张 448×448 图片是 `[2,3,448,448]`，共有 `2×3×448×448=1,204,224` 个值。像素值从 0–255 转到 0–1，再按均值/标准差归一化；DINO 路线在 `SegDataset` 中这样处理。Qwen 路线把预处理交给其原生 processor，不能照搬 DINO 的归一化参数。

- `reshape` 重新解释维度，例如 `[1,1024,768]→[1,768,32,32]`，通常还要 transpose/permute 调整顺序。
- `cat` 拼接已有轴：四路 `[B,256,32,32]` 沿通道拼成 `[B,1024,32,32]`。
- `stack` 新增轴：四张同尺寸热图叠成 `[4,B,H,W]`，再沿第 0 维平均。
- `dtype` 是一个数怎样存储；`device` 是数放在 CPU 还是 GPU。

代码事实：[train_seg.py · SegDataset.__getitem__](../../seg_cross_part/train_seg.py#L107)；[train_seg.py · SegDecoder.forward](../../seg_cross_part/train_seg.py#L209)；[evaluate_models.py · map_and_prefix](../../AnomalyGPT/followup_20261026/evaluate_models.py#L180)。

## 3. token、patch、embedding：图片怎样变成模型能处理的东西

**token** 是序列里的一个处理单元。文字 tokenizer 可以把一句话切成若干子词编号；一个词不保证恰好一个 token。**embedding** 是 token 的实数向量表示，不是词的字符串。

**patch** 是图像的小块。DINOv2-B/14 在 448×448 输入上得到 `32×32=1024` 个 patch，每块对应一个 768 维向量。另有 CLS 全局 token；密集分割需要空间位置，因此本项目取 patch token 并去掉 CLS。

**示意**：把 4×4 小图片分成四个 2×2 patch，模型先得到 4 个向量。向量 `[0.2,-0.4,...]` 不是“这个 patch 的文字”，而是网络学到的表示。相近特征可能对应相似纹理，但每一维通常不能直接命名。

代码事实：[train_seg.py · DinoFeatures.forward](../../seg_cross_part/train_seg.py#L183)。

原生 Qwen 的视觉 patch、合并和多模态位置由 Transformers 内的实现及 processor 负责。本仓库没有重新实现整套 Qwen3-VL 架构；不能把 ImageBind 的固定 16×16 格子套到它身上。

代码事实：[modeling.py · make_inputs](../../industrial_vlm/src/industrial_vlm/modeling.py#L207) 返回 processor 的 `pixel_values`、`image_grid_thw` 等原生字段。

## 4. Transformer、attention 与 q/k/v/o

Transformer 用注意力机制，让当前 token 根据其他 token 的内容更新表示。一个注意力层把输入 X 做四类投影：

```text
Q = XWq       K = XWk       V = XWv
A = softmax(QKᵀ / √d + causal_mask)
H = A V
输出 = H Wo
```

| 符号 | 意思 |
|---|---|
| X | token 表示，示意形状 `[序列长度,隐藏维度]` |
| Q / query | 这个位置想查什么信息 |
| K / key | 其他位置提供什么可匹配信息 |
| V / value | 真正被汇总的内容 |
| A | 归一化注意力权重，每行总和为 1 |
| Wo | 将各头汇总结果映射回模型表示空间 |

**示意**：问题 token 对两个视觉 token 的匹配分数为 `[2,0]`。softmax 后约 `[0.881,0.119]`。若两个 value 分别为 `[10,0]`、`[0,10]`，汇总结果约 `[8.81,1.19]`。这能说明加权汇总，不能据此断言某个注意力头在解释真实缺陷。

**多头 attention** 让多个子空间分别匹配信息。**GQA / 分组查询注意力** 允许多个 query 头共享 key/value；因此 q 和 k/v 的输出维度可以不同。本项目 LoRA 参数审计中 q/o 对应 4096 维、k/v 输出为 1024 维，后续参数计算必须按实际投影形状算，不能四个都当 4096×4096。

**因果 mask** 让生成位置不能看未来答案 token。**位置编码** 告诉模型 token 在哪里。原生 Qwen 的多模态位置由官方路径处理；迁移版本使用手工 `position_ids` 处理软提示序列。

代码边界：本项目选择 q/k/v/o 层，但 attention 核心计算在 Transformers 依赖中。选择位置见 [modeling.py · load_model](../../industrial_vlm/src/industrial_vlm/modeling.py#L75)；迁移的位置构造见 [train_qwen_matched.py · QwenCachedModel._forward_lm](../../AnomalyGPT/followup_20261026/train_qwen_matched.py#L115)。`attn_implementation="sdpa"` 是调用 PyTorch 的缩放点积注意力实现，不是新增算法。


### 补充：Transformer一层还有哪些部分

attention负责跨token汇总，但一层通常还包含归一化、残差连接和逐位置前馈网络。下面是**教学结构**，不是把Qwen依赖代码逐字抄写：

```text
X′ = X + Attention(Norm(X))
X_out = X′ + MLP(Norm(X′))
```

- **残差连接 / residual**：把原表示加回来。例如X=[1,2]、新分支输出=[0.1,−0.2]，相加=[1.1,1.8]，保留原信息并学习修正。
- **Norm**：稳定隐藏表示的尺度。LayerNorm减均值再除标准差；RMSNorm按均方根缩放，不做同样的去均值步骤。它们都不同于图片输入标准化、L2向量归一化。
- **MLP / FFN**：每个token各自经过共享的升维、非线性、降维映射，处理该位置的表示。现代语言模型常有门控变体；本项目LoRA只选q/k/v/o，没有同时对全部MLP线性层注入。
- **RoPE / 旋转位置编码**：通过位置相关旋转让q/k包含相对位置关系；多模态模型还要表示视觉时空位置。原生通道由官方实现处理，手工bridge不能只因position_ids有三个轴就称完全恢复了原生视觉位置机制。

这些运算继承自预训练依赖，当前仓库的贡献在于输入处理、精确冻结/量化/注入、训练和审计。对应使用边界见 [modeling.py · load_model](../../industrial_vlm/src/industrial_vlm/modeling.py#L75)，不应把它描述为“自行设计了Qwen Transformer”。


## 5. 视觉语言对齐是什么

视觉编码器可能给一块划痕产生 768 维向量，语言模型却接受 4096 维词向量。首先要解决**接口维度**，更难的是让数值向量具有语言模型可用的意义。

**投影 projector** 可以把 768 维变成 4096 维，但矩阵乘法只保证维度对上。只有训练和评估才能说明“这个向量让模型正确理解了划痕”。就像把 USB 接口转换成网口形状，并不等于通信协议已兼容。

三种具体办法：

| 办法 | 本项目怎样做 | 关键区别 |
|---|---|---|
| 使用底座已有对齐 | 原生 Qwen 视觉塔、merger、DeepStack→语言模型 | 沿用预训练视觉语言通道 |
| 学习额外桥接 | ImageBind 全局/局部信息→投影＋PromptLearner→LLM | 语言模型必须学会利用外接软提示 |
| 把视觉映射到文本空间 | DINO 特征→projection→CLIP 文本锚点相似度 | 用语义向量辅助分割，不必生成文本 |

代码事实分别见 [modeling.py · load_model](../../industrial_vlm/src/industrial_vlm/modeling.py#L75)、[train_vicuna_matched.py · VicunaCachedModel.forward_cached](../../AnomalyGPT/followup_20261026/train_vicuna_matched.py#L317)、[a2_language.py · LanguageBranch._sim](../../seg_cross_part/a2_language.py#L104)。

**CLIP** 是图文对比预训练模型，常用成对图文相似度做匹配。**ImageBind** 把多种模态映射到联合空间，本项目桥接实际用其视觉和文本特征。**DINOv2** 主要提供自监督视觉表征，没有本项目可以直接调用的原生文本塔。**VLM** 是视觉与语言联合模型的类别，Qwen3-VL 是具体模型系列。

## 6. 三张结构图，各自记一条链

### A. 原生 Qwen

```text
图片＋指令
  → 原生 processor（图像预处理、chat template、tokenizer、grid）
  → Qwen 原生视觉塔 / merger / DeepStack（冻结）
  → 语言 Transformer（底座冻结，q/k/v/o 上 LoRA 可训练）
  → lm_head 的词表 logits
  → 生成 JSON，或计算 true/false 的候选续写分数
```

**merger** 将视觉 token 整理到语言模块需要的表示；**DeepStack** 是 Qwen 预训练模型内部的多层视觉注入组件，本项目没有新增或重新训练它。具体内部运算应以安装的 Transformers 版本源码为准。本地 loader 将名称包含视觉相关字段的模块排除出语言量化/训练范围。

### B. AnomalyGPT 迁移

```text
图片 → ImageBind 缓存
 ├─ 全局特征 [B,1024] → llama_proj → 1 个 4096 维视觉 token
 └─ 四层局部特征 → image_decoder → 与正常/异常文本特征匹配
       → 四层概率图平均 [B,1,224,224]
       → PromptLearner → 9 个动态＋9 个基础软提示
问题文字 embedding＋以上 token → Qwen 语言模型或 Vicuna → Yes/No 回答
```

这里 Qwen 的原生视觉模块被移除，不能按路线 A 解释。

### C. DINOv2 分割

```text
图片 [B,3,448,448]
  → 冻结 DINOv2，取 4 层 patch 特征（每层 [B,768,32,32]）
  → 分层投影、卷积融合、上采样、1 通道 head
  → logits [B,448,448] → sigmoid → 缺陷概率图
     可选：文本锚点分支 / VLM 缓存特征分支
```

框、语言和概率图属于三个不同接口。一个系统可以组合使用它们，但当前每个结果必须对应其真实调用链。


### 零样本、少样本、正常训练与有监督：四种条件

| 条件 | 测试新类别前得到什么 | 本项目例子 |
|---|---|---|
| zero-shot / 零样本 | 没有目标类别示例；可使用事先规定的文本 | CLIP通用状态词匹配，不用参考图 |
| few-shot / 少样本参考 | 给K张目标类别正常图，构建参考记忆 | WinCLIP思路基线中的K=4 |
| normal-only训练 | 只用正常训练图建立模型/记忆 | 工业无监督基准常见协议；不等于没有任何学习 |
| supervised SFT | 用真实正常/异常标签及答案训练 | 原生Qwen的768来源任务微调 |

“训练类别没见过”与“测试类别没有正常参考图”也不同。给未见类别K张正常参考后仍可研究跨类迁移，但应明确这是few-shot目标类别适配。768来源、包含真实异常标签的原生实验不属于官方normal-only设定。


## 7. 冻结、训练、后训练、微调与推理

| 术语 | 在这里的具体意思 | 例子 |
|---|---|---|
| 预训练 | 模型在本项目前已有的大规模学习 | Qwen 基础视觉语言能力 |
| 后训练 / SFT | 用任务指令和目标答案继续训练 | 图片＋判断指令→`{"is_anomalous":true}` |
| 领域适配 | 让已有模型更适应工业外观和标签 | 从通用物体识别转到 VisA 缺陷 |
| 冻结 | 参数 `requires_grad=False`，不被优化器更新 | 原生 Qwen 视觉塔 |
| 参数高效微调 / PEFT | 只训练底座的一小部分增量 | LoRA A/B 矩阵 |
| 推理 | 给输入，计算输出，通常不更新参数 | `infer.py` 的单图调用 |
| 消融 | 控制其他条件，改变一个设计，比较结果 | RR/DD/RD 的任务分配对照 |

注意三个经常混淆的开关：`requires_grad=False` 控制参数是否求梯度；`eval()` 控制 dropout 等训练行为；`no_grad()/inference_mode()` 控制自动微分记录。冻结语言模型时，如果要训练其前面的 projector，仍然需要梯度穿过语言模型流回 projector，因此不能把整段前向都放进 `no_grad()`。

代码事实：原生冻结/训练模式见 [modeling.py · set_training_mode](../../industrial_vlm/src/industrial_vlm/modeling.py#L68)；桥接训练前向见 [train_qwen_matched.py · QwenCachedModel._forward_lm](../../AnomalyGPT/followup_20261026/train_qwen_matched.py#L115)。
