# Strict Qwen bridge：真实 VisA 评测与 Vicuna 对照设计

> 本文是运行前设计记录。实际采用固定 2,005 张、12 类的 square224_no_reference 开发诊断协议；已完成情况及来源复用说明见《阶段结论与续跑.md》。文中的可选 240 图调试方案并非本次主评测，原生项目 240 图确认集仍保留。

日期：2026-10-26。本文仅依据本地源码静态审查，不代表已完成真实异常推理。服务器上的最终 strict 实现、初始化与 LoRA 加载仍应由实际代码和 run.json 核对。

## 1. 本轮应固定的评测条件

- 主协议为 `square224_no_reference`：RGB 全图缩放至 224×224（bicubic），ImageBind 归一化；原始 mask 先按类别索引 `>0` 转成二值，再 nearest 缩放至 224×224。
- 这一几何与本地 `datasets/visa.py` 训练路径一致。旧 `test_visa.py` 和 `encode_image` 使用短边 224＋中心裁剪，与 strict 训练缓存的全图拉伸不同；若保留旧裁剪协议，应另命名和报告，全部模型使用相同协议。
- 使用官方 `split_csv/1cls.csv` 的 `test` 行，12 类全部覆盖。读取字段 `object, split, label, image, mask`，不从路径字符串猜标签或掩码路径。
- 第一轮可用预先固定的每类 10 normal＋10 anomaly 共 240 张调试评测，在运行前输出完整清单和 SHA256；后续全量官方 test 使用相同实现。不得按模型结果修改清单。
- 已完成模型的真实评测只做推理，不根据本轮 test 改阈值、选 checkpoint 或继续训练；若需要开发反馈，应另预留真实开发集，并说明其标签用于开发。
- 本轮官方 test 不等同于 `industrial_vlm` 自定义的 240 张确认集。两项目数据划分和评测权限分别记录，不能宣称全新数据的独立确认而忽略此前探索。
- 图像标签保留官方语义；记录原始与缩放后前景面积。小缺陷缩放后消失时保留样本，并报告数量，不把异常图改成正常图。

## 3. 三种语言指标分开记录

1. **Teacher-forcing token accuracy**：可作为训练诊断；采用标准 causal 对齐 `logits[:, :-1]` 对 `targets[:, 1:]`，只计 `target != -100`。它使用真实答案前缀，不能当自由回答准确率。
2. **自由生成**：prefix 只含用户问题和图像/软提示，逐 token 生成；主指标为完整来源分母上的正常/异常二类 Macro-F1、异常召回、正常召回、balanced accuracy、正常 FPR、invalid rate。额外报告 12 类各自结果及类别宏平均，区分“标签宏平均”和“产品类别宏平均”。
3. **候选似然**：在同一无标签 prefix 后比较 `Yes` 和 `No` 的条件对数似然，用差值计算 image AUROC/AP。若 tokenizer 将候选分成多个 token，求完整 continuation logp 的和；记录 token ID、长度、前缀边界。候选归一化得分不自动等于已校准概率。

不能假设 Vicuna 与 Qwen 的 `Yes/No` 是相同单 token。须以完整文本 prefix＋continuation 的 tokenization 验证边界；若 BPE 改变 prefix 末 token，应把共同、稳定的分词前缀作为条件，确保候选仅在答案处分叉。两个候选采用完全相同的视觉和软提示，真实标签只参与事后评价。

生成失败、超长、无 Yes/No 的样本都保留。异常 recall 的分母是全部异常来源；无效回答算未检出。正常 FPR 定义为预测 Yes 的正常来源数／全部正常来源数，同时报告正常 invalid rate，避免把拒答解释成可靠正常判断。Macro-F1 不得只在可解析回答上计算。

## 4. 像素与图像指标

- 图像热图分数固定为 `anomaly_map.max()`；将其 image AUROC/AP 与语言候选分数的 AUROC/AP分别报告。
- 像素指标使用原始连续异常图，不先二值化预测、不逐图 min-max 归一化；GT 是二值前景，统计 Pixel AUROC 与非插值 average precision。
- 每类将该类所有测试图（正常图也包含在内）的像素合并计算，再对 12 类等权平均；同时可以附全体 pooled 值，但不得混称。
- 保存 float32 `.npy` 异常图，逐图 JSONL 保存图像、类别、标签、答案、解析值、候选分数、map分数、延迟、checkpoint与协议标识。保存失败行和异常堆栈。
- 像素众多不代表有同等数量独立样本。比较模型时按源图配对 bootstrap；三 seed 汇总明确训练随机性与测试来源重采样的区别。

## 6. 正常参考分支与公平 Vicuna 对照

原训练 forward 在约一半 batch 中用正常参考的原始 patch 最近邻距离图 **替换** 文本匹配图，PromptLearner 消费替换后的图；像素 Focal/Dice 仍对上游文本匹配图优化。它不是单纯“给decoder加正常参考”。原推理在 `normal_img_paths` 非空时也替换异常图。此前 strict 缓存训练的记录未展示该随机替换，因此应先核对最终服务器实现。

本轮 no-reference 主表的全部模型均显式关闭参考。参考实验另设 `square224_kshot_reference`：从官方 train-normal 预先固定相同路径与相同增强；记录 k、文件SHA、是否允许这些来源用于训练，不从 test-normal 选参考。不能将有参考的 Vicuna 与无参考 Qwen 直接归因于语言层。

公平对照至少固定：

- 相同官方 train/test 和缓存来源、同样的 synthetic variant及mask、同样采样顺序、同样 batch/更新次数/损失系数。
- 相同 ImageBind、decoder 初始参数与文本原型；PromptLearner 的 warm-start来源和可训练范围一致。隐藏维一致并不保证旧语言投影已适配新语言空间，记录各自桥接层初始化规则。
- 只替换语言骨干及必要接口；Qwen原生视觉塔/merger/DeepStack不参与。主表冻结语言层，LoRA作为单列；若比较LoRA，明确rank、目标模块及实际参数量。
- 明确预训练 checkpoint 曾使用的训练数据；本轮 cache 路径互斥不能替代 warm-start 数据权限审计。
- 通用 PandaGPT 图文混训、参考图替换、模板、终止规则均应一致保留或一致关闭。若为简化而一致关闭，将结果命名为受控迁移 pilot，不称完整原论文复现。
- 同一物理预算下记录各自显存和耗时；不同 tokenizer 的 token数不同，steps相同并不等于计算量相同。

推荐首张真实表：`初始化Qwen / 冻结Qwen seed42/43/44 / Qwen LoRA seed42/43/44`，统一评测现有checkpoint。之后补 `Vicuna 同数据同预算`。若语言候选与热图差距很大，再用相同 checkpoint 做“原软提示／零软提示／跨图打乱软提示”推理诊断，不先增加训练模块。
