整理日期：2026-11-05。覆盖 **140 道问题**，从项目叙述到代码、数学和研究设计。它是当前实现与证据的复习提纲，不代表可以穷尽所有面试问题。数字按当前冻结报告，历史实验和最新主线分别表述。

## 一、可以直接练习的项目陈述

### 1 分钟版本

> 我做的是 Qwen3-VL-8B 在工业异常检测上的多模态适配与后训练。前期探索过原生 QLoRA 和 AnomalyGPT 迁移，发现直接换模型很容易混入接口、数据和评价问题。后来先修复 mask、几何对齐、特征维度及定位训练链路，重训 BigDec，再固定共同视觉前端，分别为 Vicuna 和 Qwen 重训桥接。在自定义 VisA 开发验证集上，三 seed 平均 AUROC 从 88.97% 到 92.58%。随后实现 q/v LoRA，只更新 383 万参数，继续研究桥接联合适配、配对排序目标和结构化空间输出。开发集最好排序方案达到 94.73%，但冻结后的 MVTec 外评中排序收益没有复现，误报反而增加。这个项目最有价值的部分，是把多模态接口、参数高效微调、目标设计和可复核评测做成了完整实验链，同时能解释成功与失败的边界。

### 3 分钟版本

> 任务是给工业零件图判断是否异常，并尝试提供位置。项目有两条主要语言路线：一条保留原生 Qwen3-VL 视觉接口，用 NF4 QLoRA 做判断与区域指令 SFT；另一条复用 AnomalyGPT 的视觉证据，把 ImageBind CLS 和异常概率图映射到 Qwen 语言空间。它们是分支实验，不能把各自最好的数字拼成一条提升曲线。
>
> 迁移早期表现不稳定。我没有直接将原因归给 Qwen 能力不足，而是逐层检查监督和接口：真实 mask 的前景是 1–8 的标签值，相关旧定位训练却按 255 归一化再阈值化；另有 mask 后缀、图像与 mask 变换不同步、ImageBind 的 token/batch 轴等问题。修复后重训 BigDec，定位 AP 明显提高。随后双方共享同一个冻结视觉前端，以同 seed 初始化桥接、同采样顺序和预算重新比较语言模型，得到 Qwen 的三 seed 配对排序增益。这里两个 LLM 原权重都冻结，学的是约 1.116 亿参数桥接，不能说成直接替换就提升。
>
> 接着做真正的语言后训练：C 冻结桥接，仅在 72 个 q/v 模块注入 r8、alpha16 的 LoRA，共 3,833,856 个参数；D 同时以更小学习率更新桥接；R 在同类别正常/异常配对 CE 控制上加 softplus 排序损失；S 从 C 的已有 adapter 继续训练 Yes/No、bbox 和九宫格位置。每个方案都保存 best/final、原始预测、梯度和冻结审计，并做独立进程重载。
>
> 我最重视对照结论是否站得住。R 的开发 AUROC 高，但外部相对匹配 Cpair 的 AUROC 和 F1 都下降；S 的严格格式有效率提高，但框 IoU 没有同步提高；原生模型自主 ROI 工具 380 次都选择直接回答，没有得到工具收益。外评共 7 模型×3 seed×1575 图，冻结权重、提示和规则后统一运行。项目体现的是领域 SFT、多模态接口、目标与评测设计能力，跨域部署和精确空间理解还需要继续研究。

## 二、项目叙述与贡献边界（Q001–Q012）

### Q001：用一句话介绍这个项目。

答：围绕 Qwen3-VL-8B 的工业异常领域适配，研究原生 QLoRA、AnomalyGPT 视觉语言桥接和语言 LoRA 后训练，并通过配对对照及冻结外评区分同域收益和跨域失效。输入是工业图像，输出从异常判断扩展到粗空间框；精确定位和生产部署尚未验证。

### Q002：为什么选工业异常，而不是通用 VQA？

答：缺陷往往小、稀疏，正常外观又跨零件差异很大，正好暴露 VLM 的细粒度视觉、跨模态对齐与域外误报问题。任务还提供像素 mask，可将“会回答”分解为排序、决策、格式和位置四个可测量问题。

### Q003：项目核心研究问题是什么？

答：先问固定视觉证据并重新学习接口后，Qwen 语言骨干是否比 Vicuna 更适合当前异常任务；再问仅更新语言低秩参数，能否进一步改善排序、召回和空间输出。前者由 Phase1 支持开发集配对结论，后者由 C/D/R/S 及外评给出有条件的结果。

### Q004：你做了基座预训练吗？

答：没有。使用已有预训练 ImageBind、DINOv2 和 Qwen/Vicuna，项目训练的是定位头、桥接与语言 LoRA，属于下游多模态适配和监督后训练。能够讨论预训练知识如何迁移，但不能把领域 SFT 包装成从零训练基座。

### Q005：“替换 LLM”究竟替换了什么？

答：最新 Phase1 保留共同 ImageBind 与 BigDec，以新的 CLS 投影和 PromptLearner 产生 19 个软 token，送入冻结的 Qwen 或 Vicuna 语言模块。Qwen 原生视觉塔没有参与这一配对；模板和 tokenizer 必须随语言骨干正确更换，桥接也分别重训。

### Q006：为什么早期 Qwen 更差，现在却更好？

答：早期至少有 16 步、32 曝光的极小 pilot，以及同时改变视觉路线的另一组实验。后续修复相关定位数据链、重训共同 teacher、重新初始化桥接，预算扩为 6000 曝光，并核对模板、监督和完整 val。旧负结果成立于旧设置；多项因素同时改变，无法把反转全部归因某一个 bug 或“Qwen 更强”。

### Q007：0.9258 对 0.8897 是怎么比较的？

答：12 类、380 图的自定义 VisA 开发 val，双方使用同一视觉缓存和定位器、同 seed 桥接初始张量与采样顺序，各训练桥接 1500 更新、6000 曝光。AUROC 由首答案 Yes−No logit 差计算，三 seed 均值分别 .925779 与 .889684，平均差 +3.6095 个百分点；不是外部测试或生成准确率。

### Q008：你最有价值的技术点是什么？

答：选择能完整解释的两个点：一是把语言模型迁移拆成可审计的视觉证据、桥接和语言更新；二是为排序训练补上严格匹配 Cpair，避免把采样变化冒充损失收益。再以失败的外评说明这些控制如何改变结论，而不只列一串高分。

### Q009：与直接训练分类器相比，大模型增加了什么价值？

答：它提供统一语言输出、指令接口和尝试结构化空间回答的基础，语言 LoRA 也能低参数适配领域任务。但当前没有同预算强分类器的完整端到端优越性证明，二分类任务上还须比较分类器的精度、校准、延迟和资源。不能仅凭用了 8B 就认定方案更优。

### Q010：为什么不直接宣称达到 SOTA？

答：训练包含真实异常及 mask，自定义划分、开发选点、输出和评价协议都与许多 normal-only 论文不同；也没有覆盖所有强基线的统一重跑。因此报告的是当前协议下的配对结果，不能与论文表格最高数字直接排名。

### Q011：项目哪些方向验证失败了？

答：原生多任务 RD 没有证明整体优于单任务；normal memory 定位弱；KD 对不同特征不一致；R 的开发排序收益未迁移到外部；S 格式变好但框定位弱；自主 ROI 工具实际调用为零。失败是下一步设计依据，需要同时说明对照和可能混杂。

### Q012：Real-IAD 跨零件分割和当前 Qwen 主线是什么关系？

答：它是前期独立的视觉分割与泛化研究，采用冻结 DINOv2 特征和分割 decoder，按零件类别划分 unseen 类，帮助认识局部特征、泄漏与跨域难点。其四 fold 不是后期语言模型三 seed，也不是当前模型 checkpoint 的连续前序。

本组证据：[演进清单](Qwen迁移实验演进与训练清单.md)、[Phase1 结果](../migration_20261103/PHASE1_RESULTS.md)、[最终报告](../migration_20261103/advanced_20261104/FINAL_REPORT.md)。

## 三、数据、监督与划分（Q013–Q026）

### Q013：主线数据一条样本包含什么？

答：至少有图像路径、category、split、二元 label，以及缓存关联索引；异常样本有可追溯原始 mask。语言输入使用图像提取的 CLS/map 与通用问题；训练标签决定 canonical 答案或结构化目标。评价标签可以存在元数据里，但不能被模型 forward 当作输入。

### Q014：主线 train/val/test 各多少？

答：修复后主线自定义 train9985，其中正常9253、异常732；val380，正常172、异常208；历史 test456。train 使用真实异常，和官方正常训练协议不同。456 图已多轮参与开发，应称历史开发测试，不能再当未见盲测。

### Q015：为什么训练时正常异常各占一半？

答：原始候选池正常占多数，平衡曝光降低只回答 No 的容易解。每 run 6000 次曝光，正常与异常各3000，属于重采样训练分布。平衡训练不等于部署异常先验50%，也不保证未经校准的阈值可直接迁移。

### Q016：6000 曝光等于看过6000张独立图片吗？

答：不等于。采样允许重复，曝光是图片被送入训练的次数，独立源图数应按 path 或内容 hash 去重。也不能把6000/9985简单称为完整 epoch，因为平衡、有放回采样和类别分布改变了访问机制。

### Q017：原生 QLoRA 的数据为什么又是768张？

答：那是独立 `industrial_vlm` 分支：VisA10821源图先按7575/1624/1622自定义划分，再选12类×每类32正常、32异常，共768训练源图。RR/DD/RD各曝光1536次，不能与主线 train9985 或 val380混写。

### Q018：RR、DD、RD 各代表什么？

答：同一768源图各曝光两次，RR两次区域任务，DD两次判断，RD一次区域一次判断；三臂192更新、micro1×accum8。控制源图顺序和初始化，改变任务分配；区域答案更长，因此同图像曝光不等于同监督 token 或计算量。

### Q019：mask 前景为什么不能除255再大于0.3？

答：VisA 某些 mask 是类别索引1–8，背景0；1/255至8/255都小于0.3，前景会被清零。真实标签应以原始值>0二值化。若另一分支是0到1的合成 soft mask，阈值语义不同，不能全仓统一无脑替换。

### Q020：异常 mask 缺失时为什么不能当正常？

答：这会将无法读取标注的异常图变成负监督，损害定位训练并掩盖数据错误。应核对图像与 mask 的目录映射、大小写和后缀，异常缺失或歧义直接报错；正常图允许无 mask，但 label 与非空前景冲突也要拒绝。

### Q021：图像和 mask 为什么要同步变换？

答：如果图像短边缩放再中心裁剪，而 mask 直接拉伸，相同像素坐标已经不是同一区域。修复路径统一 square224，RGB 用 bicubic、标签用 nearest。改变几何也会改变缺陷大小和形状，因此应固定并写入缓存身份。

### Q022：为什么 mask 转 bbox 要用全分辨率标注？

答：先在原图上取全部非零前景的 union box，再归一化到0..1000，能避免小缺陷先缩到224后消失或边缘量化失真。最小边向下取整，最大独占边向上取整，保证目标框覆盖原前景；它是粗空间监督，不是像素分割。

### Q023：怎么防止同一图出现在训练和外评？

答：先审计显式源图 ID/path，再计算文件内容 SHA，排除改名但字节相同的图片；外部清单还排除了历史已 query 的150图。SHA无交集只排除字节级重复，不自动排除近重复、同零件相邻视角或公开基座预训练暴露。

### Q024：MVTec1575 是怎么来的？

答：官方 test1725 扣除全项目历史150张已评分 pilot，保留1575图，392正常、1183异常、15类；与全 VisA10821 字节 hash 交集0。清单、模型、提示、源码与规则冻结后统一评估，所以是本轮未用于调参的外部核验，不是绝对未知基座预训练数据。

### Q025：为什么不把外评结果拿回来继续调阈值？

答：可以开展下一轮研究，但一旦用这些结果选阈值、prompt或checkpoint，这批数据就转为开发用途。当前冻结结论应保留，并为新方案另准备校准集和新留出集；否则“外部验证”名称会与实际使用方式冲突。

### Q026：Real-IAD 多视角为什么需要 part group 和近重复分组？

答：同一零件的多个视角或近重复图若跨 split，会让模型通过实例外观而非异常规律获益。前期按类别做 unseen fold，同时需要实例/近重复审计；完整类别留出与随机图片划分回答不同问题。四 fold 衡量类别迁移，不能用三 seed 替代。

本组证据：[主线协议](../migration_20261103/PHASE1_PROTOCOL.md)、[原生 QLoRA 报告](../industrial_vlm/reports/multitask_v2/实验报告.md)、[结构化几何代码](../migration_20261103/advanced_20261104/structured_geometry.py)。

## 四、指标、统计与结果解释（Q027–Q042）

### Q027：AUROC 的直观含义是什么？

答：随机取一张异常图和一张正常图，异常分数更高的概率，分数相同时计半分。它衡量排序，不要求固定阈值。AUROC .9258不是92.58%图判对，也不能直接推导部署误报或异常召回。

### Q028：为什么同时看 AP？

答：AUROC 对正负总体排序有用，但大量正常像素下仍可能掩盖低 precision；AP 更关注正例检索质量。AP受异常基率影响，外部图像异常比例75.11%，随机排序 AP 的基准也较高，因此跨数据集不能仅比较 AP绝对值。

### Q029：Pixel AUROC 高、Pixel AP 很低说明什么？

答：正常像素远多于缺陷像素时，大部分背景容易排对，AUROC仍可高；少量高分背景却会使异常检索 precision 很差。应结合 AP、分割可视化、前景比例和阈值指标，而不能只以AUROC判断可用定位能力。

### Q030：为什么分数用 logit(Yes)−logit(No)？

答：在相同上下文中，两候选 log概率之差等于对应 logits差，softmax归一项抵消。它提供连续排序且避免 sigmoid 饱和造成额外并列。模型还可能偏好第三个词，所以该分数不等同完整词表 greedy 首词或实际生成答案。

### Q031：把该分数过 sigmoid 就是真实异常概率吗？

答：它只是限制到 Yes/No两候选后的相对概率；训练重采样、域偏移、模型置信度和生成模板都会影响校准。要讨论真实概率，需额外校准数据、可靠性图或 Brier/ECE 等分析，当前外评不能反向承担校准职责。

### Q032：为什么 AUROC 上升而 F1 下降？

答：AUROC汇总阈值无关排序，F1由具体决策或自由生成产生；分数整体漂移可能改善排序却提高固定阈值误报。外部 C/D/R 就展示了这种取舍。还要检查 score与生成是否同一路径，不能把两类F1混报。

### Q033：Macro-F1 是按12类别平均吗？

答：主表生成 Macro-F1 是正常/异常两个标签 F1 的平均。另有先在每个产品类别计算、再等权平均的 category-macro 指标，两者概念不同。必须给出名字、分母与实现，不能都简称“宏平均”。

### Q034：格式无效输出如何计分？

答：保留为 abstention −1，准确率算错，在两标签 F1 中对其真实类贡献漏失，不从分母剔除。FPR只统计正常图显式 Yes，invalid另报；否则全无效模型会有看似很低的 FPR。定位中 invalid、No和缺框在全异常分母计0。

### Q035：为什么低 FPR 可能是假象？

答：模型全答 No 或大量 abstain，都可获得低显式误报，但异常召回极低。早期 LoRA塌缩和工具模型漏检202/208就是例子。应联合报告Recall、FPR、invalid、混淆计数及F1。

### Q036：三 seed 都提高就能说统计显著吗？

答：不能。三 seed只反映同一数据上有限训练随机性，样本少，且开发集被多轮使用。可以说三个预定seed的AUROC方向一致，并给出逐seed差、均值和波动；显著性需要合适的配对统计设计并考虑选型与多重比较。

### Q037：图像 bootstrap 与多 seed 各回答什么？

答：固定模型的图像配对 bootstrap描述当前样本集的不确定性，多seed描述训练随机性；单独一种都不覆盖另一种。原生QLoRA报告的bootstrap没有训练seed波动，不能据区间直接推断重复训练稳定性。

### Q038：best 与 final 为什么都报告？

答：best反映预定开发选点规则，final是固定训练预算终点，能揭示过拟合或继续训练退化。只报best容易隐藏选中step0和后期下降。B的best均值约.9272，但final约.9177，两者支持的结论不同。

### Q039：按 val AUROC 选 best 后，再报 val AUROC 有何限制？

答：它是选择后的开发表现，存在模型选择乐观性；不能当独立泛化估计。仍可在同规则、同预算配对中用于开发决策，但最终方案要用冻结留出核验。teacher也在同val选点，进一步强化其开发角色。

### Q040：全局 AUROC 和类别宏 AUROC 为什么差这么大？

答：全局包含跨类别正负图对，类别宏只衡量类内排序后等权平均。R外部全局.703438、类别宏.826927，提示分数跨类别可比性存在问题；全局93.24%正负配对跨类，但这只是诊断，不能直接证明唯一退化机制。

### Q041：外部没有 Vicuna，能否说 Qwen 跨域优于 Vicuna？

答：不能。外部21组是7种Qwen方案×3seed，没有对应Vicuna臂。Phase1支持共同视觉协议下的同域开发配对，而外评支持Qwen分支之间的域外比较；需要冻结Vicuna完整方案后单独补外部对照才能回答骨干迁移问题。

### Q042：怎样向业务解释这些分数？

答：先给预期缺陷基率、漏检代价和误报处理能力，再看固定决策点的Recall/FPR与成本。例如外部FPR约65%即正常件大量告警，即使AUROC有小增益也不代表可上线。当前报告适合研究选型，部署须增加校准、产线分层和新留出验证。

## 五、视觉表征、定位与桥接（Q043–Q058）

### Q043：ImageBind CLS 和 patch 特征有什么区别？

答：CLS提供整图语义压缩；空间patch保留位置网格，适合训练定位decoder。当前桥接同时使用1024维CLS与BigDec概率图，前者补全局上下文，后者提供异常空间证据；不能把CLS当成具备像素级位置信息的替代品。

### Q044：ImageBind 特征轴的 bug 有什么后果？

答：原特征为[257,B,1280]，其中257是CLS加256patch。若当作batch-first，样本轴与token轴混淆，可能产生错误批次融合或不对应的空间图。修复后转[B,256,1280]，去CLS，并做逐图、批次和层输出shape检查。

### Q045：BigDec 做了什么，是否训练了视觉塔？

答：它将冻结ImageBind中间patch特征变成224²异常logits/概率图，本项目重训的上采样decoder有5,409,537参数。ImageBind权重冻结，损失是GT mask的稳定focal与Dice；定位器训练不等于视觉encoder微调。

### Q046：为什么 BCE 要从 logits 计算？

答：`BCEWithLogits`将sigmoid和对数合并，数值更稳定；先sigmoid再clamp会在极端区间改变或截断梯度。focal因子也应与稳定logits损失匹配。修复后整体定位改善，但因为架构和预处理也变了，不能把全部AP差额归给数值公式。

### Q047：Focal 和 Dice 各解决什么？

答：Focal降低容易像素的相对权重，聚焦难点；Dice比较预测与前景整体重叠，缓解前景稀疏时仅靠背景降低损失。两者仍受mask质量、缺陷尺度和采样影响，不能自动解决域偏移或保证校准概率。

### Q048：为什么相同4096维仍需要重训桥接？

答：维度相同只代表接口可拼接，两个语言模型的embedding坐标、分布和语义方向不相同。Vicuna空间学到的软提示不一定被Qwen解释成同样证据。重训bridge让图像信息在目标语言模型的表示空间中变得有用。

### Q049：桥接到底有多少参数，为什么不是“18个向量”？

答：PromptLearner是将224²map转换为18×4096输出的网络，参数107,416,504；CLS Linear(1024,4096)含4,198,400参数，共111,614,904。18指输出token数，不代表只有18×4096个直接可训练向量。

### Q050：为什么要同时给1个CLS与18个map token？

答：CLS提供全局外观和物体上下文，map token编码异常分布；把二者拼成19个token后供语言注意力融合。是否每一类信息都必要，应做去CLS、去map、参数匹配和训练匹配消融；单次推理遮蔽不能完全替代独立训练对照。

### Q051：冻结 LLM 为什么反向传播还很耗显存？

答：bridge要通过LLM输出损失获得梯度，必须保留与输入相关的中间计算图；只是无需为冻结权重保存梯度和优化器状态。若把整个语言forward包进no_grad，bridge会失去梯度。C还需保留LoRA相关激活，所以“只训小参数”不等于显存只剩小模型规模。

### Q052：定位提升能完全归因于修复mask吗？

答：不能。实际同时修正mask、路径、几何、轴、损失和加载，并更换、重训BigDec。统一口径旧linear→新BigDec的Pixel AP .039255→.393868证明整体管线改善；若要拆贡献，需要固定其他条件逐项回退或阶乘消融。

### Q053：normal memory 路线是什么，训练了吗？

答：收集冻结视觉特征构成正常记忆库，用相似性/距离形成异常图，尝试分辨率、pre/post特征和16/64-shot等12格。该阶段是建库与推理，没有梯度更新head；其低AP不能直接证明这些特征经监督训练也无异常信息。

### Q054：Qwen pre-merger 与 post-merger 特征有何取舍？

答：pre保留更细空间网格，post聚合后token更少、语义更集中，但可能损失微小缺陷位置。项目在224/448等配置上训练独立SpatialHead比较；结论仅是当前头、数据和预算下的经验，不能说某层天然更好。

### Q055：知识蒸馏用了什么目标，是否始终提高？

答：空间头训练使用GT focal+Dice，加0.5×student与train-only teacher概率图的L1。pre448的AP .336404→.327643下降，post448则小升；收益不稳定。teacher误差、损失尺度和GT冲突都是候选原因，需要新消融验证。

### Q056：teacher-free student ROI是什么意思？

答：推理时由Qwen视觉特征＋已训练SpatialHead生成map和crop，再把原图与ROI送入冻结原生Qwen，不加载ImageBind/BigDec。GT head训练用过mask，KD head还用过teacher监督，所以“推理无teacher”不等于无teacher训练或零样本。

### Q057：ROI覆盖缺陷就一定能让LLM识别吗？

答：不能。学生ROI的90个漏检中，后验诊断有43个crop完全覆盖GT，说明仅解释为crop偏移不成立。还可能涉及缩放、局部对比、语言决策偏置或视觉表示，需分别测试；覆盖率是后验几何诊断，不是模型确实关注缺陷的证据。

### Q058：map干预能证明模型理解空间吗？

答：zero、相反标签donor和shuffle能测内容、分布或位置敏感性，但非分布内独立训练臂，donor还依赖评价标签做诊断选择。性能变化说明模型依赖这类输入，不能证明它恢复正确bbox或形成物理异常解释。

## 六、Qwen 接口、序列与生成（Q059–Q072）

### Q059：language-only 与完整Qwen3-VL有什么区别？

答：language-only用外部特征软token和普通文本位置，不喂Qwen视觉tower、native image token mask或DeepStack；完整原生路线使用官方processor、image grid、视觉merger、三轴位置及DeepStack。它们不是仅开关同一个图像token的等信息实验。

### Q060：为什么要使用各模型自己的 chat template？

答：预训练/指令训练形成了角色边界、BOS/EOS和assistant前缀习惯，模板错会改变模型看到的任务。Qwen用其ChatML模板，Vicuna用对应USER/ASSISTANT及BOS。必要模板差异随骨干变化，因此配对不是数学上绝对单变量。

### Q061：Yes/No为什么必须核对token边界？

答：分数读取的是指定候选token，训练首目标也必须是同一token；前导空格、大小写或模板连接可能产生不同分词。若Yes由多个token构成，只取第一token并非完整答案似然。当前实际词表校验Yes/No单token及答案首位一致。

### Q062：causal shift怎么写，为什么prefix长度要减1？

答：位置t的logits预测t+1 token，训练用logits[:, :-1]对应labels[:, 1:]。若前缀长P，第一个答案位是P，预测它的logits位是P−1；直接取P会读取已经喂入首答案后的信息，造成评分泄漏或错位。

### Q063：assistant-only loss如何实现？

答：视觉token、问题、角色模板与padding对应labels全部置−100，只保留assistant目标和EOS参与CE。注意attention mask决定可见上下文，labels mask决定监督位置，二者作用不同；不能把−100误用为embedding或attention token。

### Q064：为什么答案loss下降不等于图像理解提高？

答：canonical答案含固定措辞和EOS，teacher forcing下后续token已看见正确Yes/No，模型可能主要学会固定后缀。当前native两类答案含EOS均11tokens，loss是全部目标token平均；仍须单独测首答案排序和真实生成，不能只报train loss。

### Q065：MRoPE 是什么，language-only需要伪造视觉位置吗？

答：Qwen原生多模态位置编码使用时间/高/宽等轴组织视觉位置。language-only协议只传普通单调文本position，三旋转轴相同，不假装19个软token是原生图像网格。原生视觉分支必须按官方grid和位置逻辑执行。

### Q066：DeepStack为什么容易在手写forward时出错？

答：原生视觉除主视觉token外还向部分语言层注入多层视觉特征；只替换inputs_embeds而漏掉注入mask或层对齐，会与官方模型语义不同。项目对同形状prefill、cached decode和replay做官方/manual logits exact核验。

### Q067：KV cache缓存的是什么？

答：缓存每个注意力层已处理token的K/V，后续生成只计算新token，同时复用前缀。多模态prefill包含图像/软token，下一轮position和cache长度须正确推进。训练一般不需要cache，生成中重复prefill会增加延迟。

### Q068：为什么cached与full forward不一定逐位一致？

答：BF16、矩阵shape和kernel路径不同会产生舍入差异；官方模型自身不同shape也可能不同。判断手写实现应先比较相同batch/sequence形状与相同策略，再区分正常数值差异和接口bug。不能遇到非零误差就宣判实现错误。

### Q069：score>0和greedy回答Yes为什么不总一致？

答：候选分数只比较Yes/No，greedy在完整词表取最大，可能先生成其他词；当前部分score是batch forward、生成是逐图cached forward，也有数值路径差异。故分数阈值决策与真实生成必须分别存储、评价，不能相互替代。

### Q070：native baseline高invalid是否意味着视觉完全失效？

答：不意味着。baseline问题未强制Yes/No开头，许多回答以Based/In起句，而parser锚定首词；map臂又接受了canonical格式监督。高invalid混合格式与内容问题，不能把训练后全部生成增量归给视觉信息变强。

### Q071：把max_new_tokens调大能自动修复invalid吗？

答：不能保证。若正文前缀不符合锚定规则，后面再出现Yes/No仍无效；增大长度还改变成本和协议。历史原始记录也缺少完整stop reason时，不能仅凭末尾无标点统计“精确撞上32token上限”的次数。

### Q072：batch生成的正确性怎么检查？

答：先固定左padding、position、EOS和stopping策略，在预定小集比较scalar与batch完整token IDs，完全一致才启用；失败时按既定规则回退并保存policy。小集parity只是工程gate，非所有图片逐token一致证明，fresh/external必须强制既存policy。

## 七、LoRA、QLoRA与优化器（Q073–Q090）

### Q073：写出LoRA公式并解释形状。

答：`y = W₀x + (α/r)BAx`。若W₀为[d_out,d_in]，A为[r,d_in]，B为[d_out,r]，训练参数从d_out×d_in变为r×(d_in+d_out)，W₀冻结。当前r8/alpha16缩放系数2；模型完整映射仍是大模型，不是用低秩替换全部权重。

### Q074：为什么先选q_proj/v_proj？

答：这是较小更新预算的起点，Q影响注意力查询，V影响传递内容；实际72个模块共3,833,856参数。它是待验证配置，不是已证明最优。下一步可比较q/k/v/o或MLP，但须控制参数量、预算和验证选择次数。

### Q075：为什么不是所有attention矩阵shape都相同？

答：模型可能使用分组查询注意力，K/V输出维度与Q不同，参数计数必须读实际Linear的in/out_features。不能用“层数×两个4096²矩阵”粗算LoRA。最终应遍历实际注入模块和A/B张量核对3,833,856。

### Q076：LoRA A第一步梯度为零是bug吗？

答：标准初始化A随机、B零，使初始ΔW=0；此时`∂L/∂A`含B，因此首步可为零，B应获得有效梯度。B更新后A才有非零梯度。项目检查零adapter与起点logits一致、首步B与第二步A梯度，避免把正常现象当失败。

### Q077：零adapter为什么要与A起点exact比较？

答：注入应在step0保持相同函数；若不一致，可能改了dtype、加载错bridge、切换了dropout/模式或模块包装逻辑。该检查确认新增LoRA前后起点可比，但只覆盖预定probe，不能代替后续训练、保存和回载审计。

### Q078：后期LoRA是不是QLoRA？

答：不是。后期B/C/D/R/S语言基座BF16、训练参数FP32，无量化、无gradient checkpointing。早期原生分支才使用NF4双重量化、r16/alpha32的q/k/v/o LoRA，共15,335,424参数；另一个早期pilot的r8配置又不同。

### Q079：NF4和双重量化解决什么？

答：NF4用适合近似正态权重分布的4bit码本存储冻结权重；双重量化再压缩量化尺度等常数，降低存储开销。计算时需反量化到合适计算dtype，LoRA承担可训练增量。不能因此声称完全没有量化误差或4bit直接训练所有权重。

### Q080：量化后怎么让梯度通过冻结Linear？

答：冻结的是量化权重本身，反向仍可计算对输入和旁路LoRA参数的梯度；低秩增量保持可训练浮点张量。需核对`requires_grad`、实际导入库支持和数值稳定性，不能把整个模块放no_grad来“节省显存”。

### Q081：为什么adapter显式转FP32？

答：项目PEFT0.7.1接入时存在adapter精度随基座继承的行为，预期训练参数与优化器是FP32。显式转换后核对所有trainable dtype、梯度和optimizer身份；混合精度组合必须按实际库版本验证，不能套用另一分支环境的默认假设。

### Q082：B、C、D分别更新哪些参数？

答：B更新原桥接111,614,904参数，冻结语言；C冻结桥接，仅训LoRA3,833,856；D两者都训，共115,448,760。D桥接LR1e−5、LoRALR1e−4；B用5e−4，不能拿B退化证明所有桥接联合适配无效。

### Q083：D是不是从训练完的C继续？

答：不是。D与C都从同seed原Phase1 A桥接出发，D新注入零LoRA；S才从同seed已训练C best继续同一个adapter。弄错初始化会改变训练预算和因果解释，也会把并行分支误写为累积算法。

### Q084：为什么联合适配给bridge更低学习率？

答：bridge已经学到可用表示，大步更新可能破坏现有视觉语言对齐；新增LoRA需要较大适应空间，因此分组LR。D的当前开发收益较小，不能声称该比例最优；应在新协议下比较固定bridge、不同小LR与同曝光控制。

### Q085：LoRA比训练bridge更快吗？

答：当前C峰值allocated均值16.371GiB，B17.622GiB，但吞吐C约9.10曝光/s、B10.56。LoRA参数和优化器状态少，仍需穿过语言层反传且有旁路开销，所以该实验支持省更新参数/部分显存，不支持同时加速。

### Q086：383万参数只有原模型多少？

答：按本次保留语言基座与lm_head口径约0.0468%，相当于B桥接参数量3.43%左右。必须说明分母是哪些模块，不能把完整Qwen视觉+语言参数和语言子模块口径混用。低比例也不意味着其跨域影响一定小。

### Q087：AdamW为什么要核对参数身份？

答：仅打印trainable总量仍可能漏参数、重复参数或把冻结权重加入optimizer。需要比较模型`requires_grad`参数集合与optimizer各组的对象ID，D还要检查每组LR和无交集；训练后核验冻结张量未变化，参数组设计才真实生效。

### Q088：梯度累积与大batch完全等价吗？

答：只有损失归约、样本权重、随机性和数值条件一致时才近似。逐microbatch的token均值再平均，与整个大batch按监督token总数归一，在答案长度不同情况下不等价；BF16和dropout也会影响。Cpair/R严格匹配micro2×accum2来控制这点。

### Q089：为什么训练后既保存PEFT adapter又保存项目checkpoint？

答：标准adapter便于复用低秩权重，项目checkpoint还需桥接、配置、来源与选点信息；D必须同时保存已变bridge。仅拿adapter文件无法重建完整多模态系统，应绑定基座、bridge、teacher/cache与生成策略身份。

### Q090：保存了adapter就能精确断点续训吗？

答：不能。精确续训还需optimizer动量、scheduler步数、RNG和采样进度等；当前未保存完整optimizer/scheduler状态，只支持推理恢复或明确的新阶段继续训练。不能把从旧adapter再训练称为原中断run的精确续跑。

## 八、CE、排序目标与因果对照（Q091–Q104）

### Q091：为什么二分类还用完整答案CE？

答：它保留语言生成训练接口，既学Yes/No也学回答格式和EOS，能与结构化目标衔接。代价是固定后缀监督可能稀释判别目标；可研究首答案token loss或分类头，但需匹配数据、参数和预算，不能默认完整句CE最佳。

### Q092：为什么新增ranking loss？

答：CE优化各样本目标答案的似然，不直接要求异常图分数高于正常图；pairwise项显式推动相对排序。目标是改善连续异常分数，不是自动提高固定阈值校准。外部R的失败正说明排序目标与跨域误报仍有差距。

### Q093：R的公式是什么？

答：`s(x)=logit_Yes(x)−logit_No(x)`；`L_rank=softplus(−(s_anom−s_normal))`；`L=L_CE+λL_rank`。同类别一正常一异常组成pair；分数来自未喂答案时首答案位置，训练读取可导logits，不能复用带no_grad的评价score函数。

### Q094：为什么用softplus，而不是简单最大间隔？

答：softplus是平滑logistic排序损失，错误或小间隔pair有较大梯度，正确且间隔大时逐渐减弱。hinge也可作候选，但需要指定margin；当前没有比较两者，不能宣称softplus天然最优或稳定解决所有排序问题。

### Q095：R是DPO吗？

答：不是。它比较两张不同图的异常分数，使用真实标签配对；没有同prompt下chosen/rejected回复、reference policy的log-ratio或DPO目标。也没有reward model、在线rollout或策略梯度，准确名称是监督CE加pairwise ranking。

### Q096：为什么R不能直接对历史C归因？

答：R改为类别均匀、同类正负配对、micro2×accum2，CE归约方式和历史C可能不同。Cpair复制这些条件，只关闭ranking项，R−Cpair才较接近目标效应；R−C还混入采样与批次变化。

### Q097：为什么在同类别内配对？

答：降低“类别外观差异”比“异常差异”更易解释分数的风险，迫使比较同类正常/异常。它同时使优化更偏类内排序，未直接约束跨类分数可比性；外部全局和类宏差异提示应进一步研究，但还不能据此断言采样造成全部退化。

### Q098：lambda怎么定的，是否偷看了val？

答：用16个train-only pair测初始CE与ranking梯度范数之比，中位数约14.06366，按预先规则clamp[0.01,1.0]得到λ=1。它是尺度标定，没有按val调λ；但上限截断后也不代表两项梯度实际相等或方向协调。

### Q099：梯度范数匹配能解决多目标冲突吗？

答：不能。范数只反映大小，CE与ranking的梯度可能夹角为负，相同范数仍相互抵消；训练后梯度尺度也会变化。可在新实验记录cosine、分组梯度和动态变化，再比较固定λ或其他方法，当前只有初始尺度规则。

### Q100：ranking对score统一加常数敏感吗？

答：不敏感，`(s_anom+c)−(s_normal+c)`不变。因此仅优化pair差无法确定全局截距或保证阈值0的校准；当前CE仍提供逐样本约束，但不保证域外决策点。这个性质解释了一种可能风险，不是已确认的唯一失败原因。

### Q101：R开发集到底提高了多少，又付出了什么？

答：相对Cpair三seed均值，AUROC +1.2015pp、生成F1 +1.1825pp、Recall +5.1282pp，同时FPR +3.6822pp。不是每seed、每指标都上升，seed43贡献较大。报告应同时展示收益和误报代价。

### Q102：为什么外部R更差？

答：已知事实是相对Cpair外部AUROC−0.6143pp、F1−1.7791pp、FPR+5.6973pp，F1三seed都下降。候选解释包括域偏移、类别分数偏置和固定阈值失配，但没有单因素实验定位。不能用“过拟合”三个字冒充完整因果证明。

### Q103：怎样设计下一轮ranking改进？

答：先固定新数据角色和误报约束，保留匹配CE控制；比较同类/跨类pair混合、margin、λ与分数正则，并记录类内和全局排序、校准及成本。用新开发/校准集选择后再开新外评，不能在当前MVTec上循环调好再报盲测。

### Q104：如何证明新目标带来的是目标收益，而非多训练了？

答：从同checkpoint出发，安排同曝光、同采样、同optimizer与同选点的继续CE臂，再仅改变新目标；结构化任务还要匹配答案长度或分解监督来源。S当前缺少完全同曝光binary继续CE等单因素控制，因此新增训练与mask目标的作用尚不能完全分离。

## 九、结构化输出、定位与工具（Q105–Q118）

### Q105：S新增了什么能力训练？

答：从同seed C best继续同一个q/v adapter，使用训练mask生成Yes/No、bbox[0..1000]和3×3位置文本，额外500更新、2000曝光。bridge和语言原权重冻结，不叠新adapter，也不包含R排序损失；它是结构化监督SFT分支。

### Q106：为什么用两行Yes/No加JSON？

答：保留首答案Yes−No连续评分，同时让后续结构承载bbox和location。严格schema规定两键、整数有效边界、No/null与Yes/box一致及位置与框中心一致。它便于程序消费，但设计更规范不代表模型几何预测就正确。

### Q107：框为什么是union box，有什么缺点？

答：对全部标注缺陷取一个外接矩形，目标确定且便于单框输出；多处离散缺陷会使框包含大量正常区域，tiny defect也对坐标误差敏感。它回答粗定位问题，不能替代实例多框或像素mask指标。

### Q108：为什么严格格式有效率不等于JSON有效率？

答：JSON语法正确还可能有额外键、重复键、浮点坐标、退化框、Yes/null或location与框中心冲突。S的许多严格失败来自空间字段不一致，不能都称语法失败。评价应分别拆语法、schema、决策和几何约束。

### Q109：为什么定位分母必须用全部异常图？

答：若只统计生成合法正框的子集，模型可以漏掉难图后获得虚高IoU。全部异常图中No、invalid或无框都计0，才能反映端到端覆盖；条件IoU可以辅助报告，但必须同时给有效正框数量和覆盖率。

### Q110：S格式提高，为什么还不能说定位增强？

答：外部严格有效率从Cstructured .641270到S .919577，但全异常IoU .071108→.069815略降，IoU≥.5也下降。说明模型更会遵守结构，不等于更会保留、解码空间信息。分类AUROC改善和几何能力应分开评价。

### Q111：Cstructured为什么是必要控制？

答：它保持C权重，只换成与S同样的结构化prompt和80token预算，测新schema带来的起点变化。直接拿S对原binary C会混合prompt、输出长度、训练与监督差异；Cstructured本身没有额外训练。

### Q112：teacher框比S好能证明瓶颈在语言层吗？

答：不能单独定位。固定teacher框外部IoU .224989明显高于S .069815，说明已有map可通过另一规则产生更好的框；但差距可能来自19token压缩、bridge、坐标训练或语言解码。需要直接map接口、坐标头等对照分解。

### Q113：为什么无条件teacher框不适合直接部署？

答：按每图95分位阈值总能挑出一些像素，所以正常图也100%出正框。门控后仍有较高正常出框率。这个控制用于判断空间信息是否可提取，不证明异常决策可靠；检测系统还需可靠的“无需出框”机制。

### Q114：自主ROI工具的流程是什么？

答：原生Qwen先输出受限action，选择直接回答或请求合法crop；执行器裁剪后将观察送回模型给最终答案，记录action、实际调用、token、延迟和失败。它是独立原生视觉系统，与压缩bridge模型的提升不能混合归因。

### Q115：工具实验的实际结果是什么？

答：380/380 planner均选择answer，crop调用0；model arm与duplicate原图控制逐图logits、文本和token一致，漏检202/208异常。当前可展示工具协议、执行器和受控评测，不能说学会自主局部检查或工具提高检测。

### Q116：为什么需要duplicate、center和random控制？

答：多图输入本身会改变视觉token、上下文和决策，duplicate控制额外图像预算；center/random区分“多看局部”与“智能选位置”。仅比较单原图和模型crop无法知道收益来自更多像素、额外prefill还是选择策略。

### Q117：相同visual token就等于相同FLOPs吗？

答：不等于。planner额外生成、不同轮数、prefill/cache复用和裁剪执行都有成本；本轮双图控制392视觉token，但模型工具流程更慢。比较需要分别给encoder、planner、最终回答和端到端成本，不能仅用token数称算力完全匹配。

### Q118：如果下一步做工具训练，会怎么做？

答：先采集有益crop与直接回答示范，明确每次调用的质量、成本和可用观察，做工具轨迹SFT并保留固定crop/无工具控制；若再做RL需设计可验证reward与调用成本，另立协议。当前没有工具SFT或RL结果，不能把计划写成完成能力。

## 十、工程、复现与审计（Q119–Q130）

### Q119：为什么既保存当前源码又保存runtime源码？

答：开发目录可能后来修改，运行时snapshot和SHA能说明某个结果实际导入哪一版代码。源码、配置、输入与权重身份应一起绑定，否则Git最新代码不一定能解释旧结果。历史失败和transient版本也应保留其真实身份。

### Q120：SHA能证明模型训练正确吗？

答：不能，它证明给定字节的身份和未变更关系，不证明算法、标签或统计正确。还需要梯度、冻结、shape、独立回载和指标复算。内容hash是证据链的一部分，不能替代语义测试。

### Q121：冻结检查只看requires_grad够不够？

答：不够。还要检查梯度为None、optimizer不包含冻结参数，以及训练后冻结张量版本/内容不变；上游train/eval状态和dropout也要符合协议。某些buffer或手写更新可能绕开requires_grad，因此关键权重还应比较字节身份。

### Q122：为什么做独立进程重载？

答：同进程可能残留训练对象、cache或未保存权重，新进程从base与checkpoint重建更能检验交付是否完整。比较同样本、同batch伙伴、logits和生成token；fresh仍是原图的工程复验，不产生更多独立评测样本。

### Q123：为什么重载比较要保持原batch形状？

答：不同batch和sequence长度可能走不同BF16 kernel，产生正常舍入差异。按原batch保留伙伴可把数值路径尽量固定，若仍不一致才更容易定位加载/策略问题。exact结论的范围必须写到覆盖哪些checkpoint和样本。

### Q124：关闭adapter后回到起点说明什么？

答：它说明该重建系统的base与bridge参考一致，训练变化来自启用的低秩增量，排除一些原权重或bridge误改问题。仍不能证明LoRA学到正确因果特征，也不能单凭这一检查声称完整训练轨迹可复现。

### Q125：本机没有权重，如何完成最终审计？

答：本机可复算保存逐图预测、总体/分类别指标、样本顺序、身份链和派生结果；服务器fresh报告提供此前实际权重加载与字节核验。必须区分本机重新核验什么、依赖服务器记录什么，不能把result-only审计写成重新运行整个模型。

### Q126：缓存为什么也要绑定预处理和decoder SHA？

答：缓存中的CLS/map是模型真实输入，若图像几何、encoder或decoder变了，缓存相同文件名也可能不同。绑定source/weights/pipeline和items顺序，才能保证不同训练臂看的是同一证据；仅比较cache长度不够。

### Q127：什么情况下该先做smoke/preflight？

答：接入新adapter、目标或生成路径时，先用固定少量训练图检验有限loss、非零梯度、可过拟合、冻结和保存回载，再启动正式预算。preflight验证工程链路，不能凭8张图涨分宣称效果成立，也不应反复挑smoke图优化指标。

### Q128：训练中断后如何避免污染历史？

答：正式输出目录按run身份隔离，完整已完成结果只读跳过；失败尝试保留为明确目录，再以新run记录重新开始。没有optimizer状态时不伪装精确续跑，保留失败日志、源码和实际曝光，避免拼接不同历史成一条曲线。

### Q129：GitHub为什么不上传所有文件？

答：可交付源码、配置、协议、轻量预测/审计和说明；大模型权重、数据和大型tensor cache需要独立资产管理，凭据更不能进入仓库。复现文档明确数据与模型来源、环境和哈希，仓库完整不等于单次clone就具备全部训练资产。

### Q130：如果面试官现场要求复现一个结果，先展示什么？

答：先选一个已冻结run，打开run.json、输入/权重身份、逐图预测和复算脚本，重算指标而不重新训练；再解释服务器fresh重载覆盖范围。若现场有完整数据/权重，使用对应冻结源码和保存policy跑一个非封存样本，避免临时换版本。

## 十一、研究推进与现场推导（Q131–Q140）

### Q131：如果只允许做下一项实验，你选什么？

答：优先保留空间信息的map/patch接口或独立坐标头，并配同曝光继续CE控制。理由是teacher框明显优于S生成框，而当前19token压缩是否保留足够几何信息未分解。选择依据是可检验的瓶颈证据，不是继续堆更大LLM。

### Q132：如何减少跨域误报而不只压低召回？

答：在独立校准数据上预定FPR约束，比较分数校准、类别偏置处理或不确定性拒答，并报告约束下Recall和覆盖率；新的holdout检验迁移。阈值变大总能降误报但也可能漏检，必须展示完整取舍，且不在当前外评上调完再报成功。

### Q133：如何检验LLM是否真的使用图像？

答：在冻结协议下做图像/CLS/map置零、同类替换和错配等干预，同时记录分数、生成与类别差异；再加独立训练的去视觉控制。单次遮蔽的分布外扰动只能说明敏感性，不能完整证明视觉因果利用或正确定位。

### Q134：现场推导LoRA首步A/B的梯度。

答：令上游梯度g=∂L/∂y、z=Ax，缩放c=α/r，则`∂L/∂B=c·g·zᵀ`，`∂L/∂A=c·Bᵀg·xᵀ`；B=0时A梯度为0，B可非零。扩展到batch需求和/按loss归约平均；该推导能直接解释Q076的工程检查。

### Q135：现场计算ranking loss和梯度。

答：令δ=s_anom−s_normal，`L=log(1+exp(−δ))`，`∂L/∂δ=−sigmoid(−δ)`。δ=0时L≈.6931、梯度−.5；δ=2时L≈.1269、梯度≈−.1192；δ=−2时L≈2.1269、梯度≈−.8808。优化会提高异常分数或降低正常分数，但不固定共同平移。

### Q136：现场写mask转归一化框的核心逻辑。

答：原始mask先>0，找`xs.min/ys.min`与`xs.max+1/ys.max+1`，按宽/高缩放1000；最小边floor、最大边ceil。例10×20 mask，前景`mask[2:4,3:8]`，目标[150,200,400,400]。异常空mask应报错，正常输出null，不能默认全图框。

### Q137：现场手算一个AUROC及ties。

答：异常分数[.9,.5]、正常[.5,.1]共有4个正负pair，贡献1、1、.5、1，总和3.5，AUROC=.875。与排序位置无关，分数同值计半分；代码应调用可靠实现或正确rank ties，不能随手argsort打破并列。

### Q138：现场比较两种token loss归约。

答：样本A有2个目标token、平均loss1；B有8个、平均loss3。逐样本均值是(1+3)/2=2，合并token均值是(2×1+8×3)/10=2.6。区域目标更长时，这种差别会改变任务权重；解释为什么同样两张图、同样梯度累积不保证等价。

### Q139：现场设计一个能抓住评分标签泄漏的检查。

答：固定同图和同prompt，随机打乱评价label并要求模型输入张量、logits与生成完全不变；再核对score只读prefix末位而没有喂答案。指标应随label变化而变化，预测不应变化。此检查能抓一类泄漏，但还需数据划分和缓存来源审计。

### Q140：面试官说“你的最好方案外部更差，所以项目没有价值”，怎么回答？

答：先承认当前不支持跨域部署，再说明问题被拆解到了可验证层：共同视觉配对、低秩更新、严格ranking控制、格式与定位分离以及完整外评。负结果排除了“开发AUROC高就能泛化”等假设，下一步也因此具体化为保空间接口与误报约束。用真实结果和实验设计说明研究能力，不把失败包装成性能成功。
