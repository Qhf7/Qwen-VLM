## 1. SEEM：把提示接口统一到分割查询空间

### 1.1 核心问题与数据流

SEEM 的问题是：通用/开放词汇分割、文字指代分割、点击/涂鸦交互分割通常各用一个模型，如何让一个参数集接受不同提示乃至组合提示？它采用图像编码器、语言编码器与统一分割 decoder。它没有自回归生成答案的 LLM；语言编码器把文本映射为分割需要的语义表示。因此“支持文本交互”不等于“有通用多轮问答或缺陷原因推理”。依据：pp.1–3。

其 decoder 统一接收可学习查询 `Q_h`、文本提示 `P_t`、视觉提示 `P_v`、记忆提示 `P_m`，输出 mask embeddings 和 class embeddings（p.3，式 1–3）。Mask embedding 与图像像素特征匹配形成掩码；class embedding 与语言空间匹配决定语义。两种表示承担不同职责，不应把它们当成同一组“文本 token”。

视觉提示的关键是 **VisualSampler**：在当前图或参考图上，根据点、框、涂鸦、多边形、掩码指定的区域采样/池化视觉特征，至多采样 512 个点特征，统一成 `P_v`（p.4，式 4）。这比给每种提示另设一个语义完全独立的专家更统一。参考图区域可以替代当前图区域作为视觉提示，因而产生跨图指代能力。

训练时为不同任务复制可学习查询，但联合训练的仍是同一模型；推理时允许文本/视觉提示共同 self-attention，支持训练时未联合出现过的组合（p.4）。不同任务匹配目标也有区别：视觉提示依据 mask embeddings 匹配，文本提示依据 class embeddings 匹配，再结合 GT mask IoU（p.4，式 5–6）。不是任意提示都只与 CLIP 文本做一次余弦相似度。

### 1.2 交互记忆与训练监督

记忆提示不是通用语言对话历史。它利用上一轮预测 mask 约束 cross-attention，在之前关注的区域提取记忆，再与其它提示 self-attention，帮助同一对象的反复交互（p.5，式 7）。图像 encoder 只运行一次，后续交互主要重新运行 decoder；这适合交互成本控制（p.2）。

训练包含全景分割、指代分割、交互分割三类监督（p.5，式 8）。全景分支分类/像素 BCE/Dice 系数为 2/5/5；指代和交互分支各为 0.2/2/2。训练不是只靠无标签图像或文字描述。使用 COCO2017 全景标注，并排除 RefCOCOg 验证图，得到约 107K 图；文字指代来自 RefCOCO、RefCOCO+、RefCOCOg（p.5）。训练中会以 IoU>0.7 的 LVIS masks 替换对应 COCO masks 改善交互细节（p.8）。

视觉骨干为 Focal-T、DaViT-d3(B)、DaViT-d5(L)，语言编码器为 UniCL 或 Florence（p.6）。所谓 scratch 消融仍从 UniCL/Florence 的视觉语言主干初始化，只是不从 X-Decoder checkpoint 初始化完整模型；不能误说成完全随机初始化所有权重（p.8）。

### 1.3 “Zero-shot”具体指什么

论文存在几种不同泛化：未联合训练的文本与视觉提示组合；跨自然图/卡通等域的视觉指代；没有用视频训练的 VOS。它们不等于工业异常检测中的“目标类别无训练图”，更不意味着输入图像后自动定位所有未知异常。

- 指代/交互分割依赖用户给对象提示；交互点击的评测通过 GT 与预测误差自动选下一点击，在最大错误区域中心加点（p.6）。这是带迭代提示的分割能力，不是单次无提示异常定位。
- NoC@85/@90 衡量达到指定 IoU 所需点击数；K-NoC 规定最大点击次数。它不能和 P-AUROC 当同一指标排序（p.6）。
- 表 3 的 zero-shot video segmentation 没有用 DAVIS/VOS 或成对图训练，但需要第一帧的 mask、点或涂鸦等视觉提示（pp.7,9）。与“没有参考、没有标注的目标测试”权限不同。
- 开放词汇语义标签需要给候选词汇；不给词汇时可做 class-agnostic segmentation（p.8）。并非无任何词表就自动生成任意对象名称。

### 1.4 结果应该如何读

SEEM-L 在表 1 的 COCO PQ/mAP/mIoU 为 57.5/47.7/67.6，RefCOCOg cIoU 为 65.6；加入视觉提示组合后，RefCOCOg cIoU 为 75.1（p.6）。后者多了视觉定位信息，不能把差值全解释为“纯文本理解更强”。表 5 进一步区分文本查询/视觉查询与 self-attention 组合，说明结果受提示权限和查询读出方式影响（p.7）。

交互训练每轮前 N−1 次不回传梯度，增加交互轮次可改善 NoC；论文主结果选择 3 次，兼顾成本（p.8）。论文的细致 ablation 支持“提示组合、交互记忆有用”，没有提供“异常检测准确率提高”的证据。

### 1.5 对本项目的意义与 AnomalyGPT 边界

可借鉴的是统一点/框/mask/参考图的视觉提示入口、分割状态的记忆、避免每轮重复提取图像特征。若比赛允许人机交互或有指定参考区域，SEEM 是接口和候选区域处理参考。

它输出通用对象/区域分割；AnomalyGPT 路线关心异常判别、异常热图与语言应答的联动。SEEM 本身没有定义工业正常性、没有异常训练目标，也没有展示缺陷问答或工业异常 benchmark。即使把前景分割准，也不代表能把前景内部的裂纹、微小破损判断为异常；需要另行构建异常证据。

## 2. OMG-LLaVA：用通用感知的查询对齐 LLM 与像素输出

### 2.1 为什么它与 SEEM、AnomalyGPT 都有关

它把通用分割器的细粒度感知和 LLM 的指令跟随结合起来，目标包括整图 caption/对话、区域 caption/视觉提示对话、指代/推理分割和 grounded conversation。其结构是 **一个图像 encoder、一个通用 perception decoder、一个 LLM**。普通 LLaVA 的 image tokens 只够整图理解，另接 SAM 等专用分割器易造成多视觉编码器冗余；它用 OMG-Seg 同时承担图像 tokenization、对象 tokenization、mask decoding（pp.2–5）。本身不是多个专家路由的 MoE。

统一形式是 `T_text_out, T_object_out = LLM(T_pixel_in, T_object_in, T_text_in)`（p.5，式 1）。这里区分密集像素中心 token、对象中心 token、文本 token，避免把所有视觉信息压成一个全局 embedding。

### 2.2 实际机制、张量与提示

图像 encoder 使用 ConvNeXt-L CLIP，1024×1024 输入。先取 32 倍下采样特征，再以 pixel shuffle 降低分辨率，使 LLM 的图像 token 总下采样率为 64：`16×16=256` 个像素中心 token（p.6）。这只是 dense image tokens 的数量；还要拼接 foreground object query tokens 和用户提示对应 tokens，不等于整个 LLM 输入只有 256 tokens。

OMG decoder 接收可学习 object queries 和 point/box/mask 生成的 visual prompt queries，通过 masked cross-attention 从图像特征取信息，再 self-attention 建模对象关系。Query 可经 FFN 读出 mask 和类别（p.6）。框/mask 不是粗暴取中心点：框外像素由 attention mask 遮掉，mask 提示直接约束可注意区域，避免将框或 mask 的范围信息丢失（p.6，图 4）。

**Perception prior embedding** 是最重要的桥接：已有分割 query `Q∈R^(Nq×C)`、分割 masks `M`、query 置信度 `S` 先构成每个像素对对象的 soft assignments；对 object queries 加权，再加回 dense image feature `F`：`T_pv = M_S·Q + F`（p.7，式 2–3）。公式中的 `M_S` 按 query 维度 softmax；正文列 M 的形状为 Nq×HW、`M_S` 为 HW×Nq，排版隐含转置/广播，理解时应以每像素对所有 query 的权重为准。它是**不训练的新计算组件**，依靠冻结 OMG-Seg 的分割先验，不是学习一个额外 segmentation expert。

除了把对象信息注入像素 token，还把 foreground object queries 直接拼成 object tokens。两种视觉 token 分别通过 MLP visual projectors 接入 LLM 文本 embedding 空间；自动对象 token 和 visual-prompt 对象 token 共享对象 projector（pp.7,17）。输出 `[SEG]` 的最后层 hidden state 经 text MLP 映射回 perception query 空间，再送到 OMG decoder 生成 mask（pp.7,18）。因此 mask 并非把 LLM 生成的坐标字符串画出来，也不是从回复中任意解析普通单词。

`<Image>` 被视觉 tokens 替换；`<Region>` 被指定的对象中心 token 替换；`[SEG]` 是输出 mask 的专用占位（p.7）。这提供显式的“文字片段—mask”对应关系。推理时若 RES 没生成 `[SEG]`，论文采用 empty mask 作为结果，而不是偷偷用备用分割器补救（p.16）。

### 2.3 冻结与训练：要区分常规模式和 ft 表格

常规两阶段训练中 OMG-Seg 的图像 encoder 和 decoder 始终冻结（pp.5,7–9）：

1. Pretraining：冻结 LLM 与感知模型，训练两个方向的 projectors。除了文本生成损失，加入 object token round-trip reconstruction：`||T_ov − P_t(P_v(T_ov))||²`，约束对象信息经语言空间往返仍能被感知 decoder 消费（p.7，式 4）。
2. SFT：训练 projectors，用 LoRA 调整 LLM；mask supervision 为 CE+Dice，另有文本生成损失（p.7，式 5）。即便 decoder 冻结，loss 仍可沿其计算图传回 LLM/projector；冻结权重不等于断开梯度。

训练数据明确有整图 LLaVA 665K；Osprey 区域数据约 74K、MDVP 点提示约 200K；RefCOCO/+/g、RefClef 指代 mask 约 74K；ADE20K/COCO-stuff 约 26K；GranDf grounded conversation 200K（p.8）。所以不是零标注的“只接上一个 LLM”，其能力也不能全归于架构。

实现设定使用 InternLM2-7B，图像 1024²，LLM max length 2048；pretrain lr 1e-3、SFT 2e-4，各 1 epoch，附录写 global batch256/128、每 GPU32/16（pp.8–9,16）。主文称4张80GB A800、训练7h/48h；仅用“4×每GPU”与附录global batch对不上，可能涉及梯度累积，但该段未说明，不应自行补成已核实配置。

**冻结有特定实验例外**：表 3 同时报告普通 OMG-LLaVA、`ft + frozen decoder` 和 `ft + unfrozen decoder`。主文所谓 refCOCO 78.0、refCOCO+69.1、refCOCOg72.9 的最佳行使用了**解冻 decoder 的任务微调**（pp.8–9），不能与“感知始终冻结”的主配置混成一个系统性质。

常规冻结 decoder 行的 val cIoU 为 RefCOCO75.6、RefCOCO+65.6、RefCOCOg70.7；任务微调但仍冻结 decoder 行为77.2/68.7/71.7；解冻微调行78.0/69.1/72.9（p.8，表3）。表2汇总的78.0/69.1是最佳微调变体。横向比较时必须确认其它方法是否也使用 ft、相同数据和同规模 LLM。

OMG-Seg 不支持多粒度 part segmentation，故 OMG-LLaVA 无法做部件级分割；不能进行像素级时空推理，虽然底层OMG-Seg有视频感知能力（p.19）。所谓 reasoning segmentation without reasoning-specific data 主要是 p.19 及后续图的定性展示，主表未给独立 reasoning segmentation benchmark 的定量证据。

### 2.5 本项目可用的思想与边界

最相关的接口思想是：显式保留“局部证据 token”，再让 LLM 生成文字和专用 mask token；用往返约束/预训练减少 frozen pixel decoder 对输出查询分布的要求。若要做可解释缺陷问答，可以检查异常图特征是否真正被 LLM消费、文字描述是否与输出位置一致，而不只看回答流畅度。

然而 OMG-LLaVA 的通用 object queries 未必覆盖对象内部微小缺陷；它的 part-level 限制对工业细粒度异常尤其相关。论文没有工业异常分数、正常参考建模、MVTec/VisA异常AUC或工业异常问答实验。它与 AnomalyGPT 的共同点是让局部视觉证据和 LLM发生联系，但局部表示来源、监督目标、mask产生方向和测试任务都不同，不能用本论文的RES/GCG成绩证明工业异常检测优于AnomalyGPT。

## 3. CLAD：应先审查可复现性和证据完整性

### 3.1 正文真正定义了什么

论文将 CLAD 展开为 **Vision-Language Anomaly Detection via Contrastive Cross-Modal Training**（pp.1–2）。它定义视觉 encoder `f_v(I)` 与文本 encoder `f_t(T)`，把图和相应文字映射到共同空间（pp.5–6，式1–2）。视觉 backbone 写成“pretrained CNN or ViT”，文本写成“GPT or BERT”，没有定下可复现的具体型号、层读出或维度；也没有明确投影网络、token/patch结构。

式3用 paired image/text 的 squared distance 的 hinge拉近，用 i≠j image/text pair 的 margin项推远（p.6）。正文把它口头解释成“正常聚集、异常推开”，但公式本身区分的是同实例/异实例，并没有正常/异常标签项；也没有说明怎样构造 positive/negative 异常语义。若所有其它实例均作负例，正常图之间也可能被推远。不能仅从一个普通 paired contrastive loss 推出学到了正常性概念。

检测得分 `S(I,T)=exp(−||z_v−z_t||²/σ)`，**小值表示更异常**（pp.6–7，式4）。它数学上是图文一致性/正常性相似度；若外部评测约定正类为anomaly且分数越大越异常，需要翻转成 `1−S` 或同向距离，否则 AUROC方向会反。该式还要求每个测试图的“关联文本” `T`，但未明确其究竟是类别正常模板、产品描述、专家已知缺陷描述，还是根据图生成的文字；这些权限对公平性至关重要，不能假定无标签也不能指控已泄漏。

定位只写“可采用 Grad-CAM”，给 `ReLU(sum_k alpha_k A_k)`（p.7，式5）。没有明确对哪个标量求导、alpha如何从梯度池化、选哪层、ViT时如何构图、如何resize/normalization。该式是解释性热图模板，不是足够复现高分像素定位的完整算法。

训练说工业目标集上 task-driven fine-tuning，**视觉和文本encoder都更新**，总loss为contrastive+λreconstruction；重建通过所谓视觉/文本encoder的“逆函数”还原原始图和文本，并用平方误差（p.7，式6–7）。正文没给对应decoder结构、文本离散token如何用L2重建、λ/α/β/σ取值、optimizer、lr、epochs、分辨率、batch、数据增强、阈值选择。

### 3.2 与引言承诺之间的缺口

引言声称有 contextualized reasoning module，能生成异常文字解释（p.2）；但方法章节只定义双encoder、对比loss、距离检测、Grad-CAM和重建，没有解释生成器、LLM解码路径、指令数据或生成loss。不能据此把 CLAD 当作已实现的异常聊天模型，更不能当成 AnomalyGPT 同等功能的可复现替代。

标题中的“robust”和“efficient”没有对应的扰动/OOD鲁棒性基准、延迟/吞吐/显存/FLOPs/硬件表。正文只有 MVTec和VisA检测定位，以及人评/IoU（pp.8–11）。局部两个数据集的AUC，不足以验证实时效率或广泛鲁棒性。

训练/测试split、异常label或mask的使用、cross-category/cross-dataset协议、few-shot shot数都未明确。第8页说MVTec有3629训练、1725测试以及正常/异常样本的笼统描述，但并未说明哪些异常是否用于训练；VisA则只列总正常/异常数量。因此准确读法是“正文说在特定工业集微调双encoder，但监督权限不清楚”，不能读成目标集zero-shot、纯normal-only、标准1-shot或固定cross-dataset中的任何一种。

| CLAD | 94.1±1.1 | 95.3±0.1 | 86.1±1.1 | 96.2±0.1 |

它并非“全部数据集全部指标领先”：VisA P-AUC **低0.2**。MVTec P-AUC只高0.1，不能因文字写“significantly”就认定统计显著，尤其表中标准差范围重叠、没有配对显著性检验。MVTec I-AUC提高1.0是可从表直接计算的描述差值，不应扩大为全套协议下的SOTA结论。

进一步与本地 WinCLIP 原文核对：CLAD表1的 **四个基线**（SPADE、PaDiM、PatchCore、WinCLIP）在两个数据集的均值和标准差，均与 WinCLIP 的 **1-normal-shot** 表一致；最后一行原方法名实际为 **WinCLIP+**，不是无参考的WinCLIP。证据：`WinClip/paper.tex:226–229`（classification表）、`370–373`（segmentation表）；对应WinCLIP PDF p.7表1、p.8表4。真正0-shot WinCLIP的MVTec I/P为91.8/85.1、VisA为78.1/79.6。CLAD没有交代自己的shot/微调权限，也没在该表标明这些基线是1-shot，故不能据此作统一zero-shot排名。此处是本地两份原论文直接交叉核查，没有重新运行各基线。

表2去contrastive时I/P从94.1/95.3降到88.5/91.2；去finetuning为91.2/92.5；换CNN为85.6/89.4（p.9）。但“无contrastive的standard supervised训练”未说明替代loss；“CNN vs ViT”未确定具体型号/预训练预算，无法把差值严格归因于单一模块。没有本次运行证据。

表3人评均分CLAD4.6、WinCLIP4.4（p.10），未给人数、样本数、抽样方式、盲评、专家资历细则、方差或一致性；只能作为作者所报人评分，不能当成强解释性验证。表4 IoU CLAD0.80、WinCLIP0.75（p.11），未明确哪个数据集/宏平均、阈值及选阈值split；AUROC与IoU不可互换。引言称比较AnomalyGPT，但主结果表没有AnomalyGPT（pp.2,9）。

引用也有可核查的问题：第8页baseline SPADE指向[28]，而第13页[28]是城市交通视频分析，非异常检测SPADE来源；第4页谈ViT的[25]在第13页实际是2016年的 exemplar CNN。这些是本地文本可证实的引用不匹配，应在作为方法依据前回查原始来源。

### 3.4 对本项目的实际地位

它可以用作“图文正常性距离+对比微调”的思路线索，但目前PDF不够支撑精确复现、zero-shot协议归类、优于既有方法的公平对比或可解释LLM系统选型。不能据此直接投入构建一个未被具体定义的“CLAD推理模块”。如果确实想验证该想法，应独立写清图文pair生成、异常监督权限、target split、具体CLIP/encoder、距离方向和定位机制，并作为本项目自己的baseline实验，而不是称为已复现论文。

## 4. 三篇与异常路线的总映射

| 维度 | SEEM | OMG-LLaVA | CLAD正文 |
|---|---|---|---|
| 基本视觉证据 | 通用mask/class queries+用户提示 | OMG-Seg像素与对象queries | 图文全局embedding距离；Grad-CAM细节不足 |
| 生成式LLM | 无 | 有，InternLM2-7B等 | 声称LVLM，实际架构未落实生成路径 |
| 文本生成/多轮对话 | 非其研究输出 | 可生成文字及[SEG] | 引言承诺解释，方法未具体定义 |
| 训练监督 | COCO/LVIS mask+referring文本 | caption/对话+大量分割/区域标注 | 工业微调，正常/异常/文本权限不明 |
| zero-shot含义 | 新prompt组合、域、无视频训练VOS | 部分泛化展示；并非工业目标零样本证据 | 未建立明确zero-shot测试协议 |
| 主要输出与指标 | mask，PQ/AP/mIoU/NoC | 文字+mask，RES/GCG/MLLM指标 | anomaly score/热图，I/P-AUC及少量人评/IoU |
| 对异常项目最可用思想 | 统一空间提示、交互记忆 | 局部证据token、查询空间对齐 | 图文距离基本baseline，证据弱 |

这三篇更适合分别回答“怎样给提示、怎样把区域信息接到LLM、怎样审查图文异常检测的实证完整性”。异常性能应由异常数据、监督权限和目标指标验证；通用分割结果、语言流畅度或论文标题都不能替代这一步。
