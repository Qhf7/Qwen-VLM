# Anomaly-VL v2 框架设计

> 版本：v2 草案 · 2026-10-23
> 融合来源：**AnomalyGPT**（AAAI'24，骨架）+ **AdaCLIP**（ECCV'24，PEFT 手法）+ **Dual Anchors**（CVPR'26F，DINOv3 主干）
> 配图：[`AnomalyVL_v2框架图.png`](AnomalyVL_v2框架图.png)（正文内已嵌入）
> 论文精读：见文末 §12，原文 PDF 与图在本地 `文献阅读/` 与各论文目录，未入库
> 前置证据：本项目实验节点 I-17 ~ I-30（见《实验进度与版本记录.md》）

---

## 0. 一句话

> **VLM 不再当"全能模型"，只当"语言大脑"；视觉外包给冻结的 DINOv3；像素定位由轻量解码器负责，再把定位图变成 9 个 token 回灌给 LLM。**

---

## 1. 为什么要改（v1 的四个失败）

v1 = 直接对 Qwen3-VL-8B 做 LoRA SFT（视觉塔 + LLM 一起）。实测暴露四个问题：

| # | 现象 | 证据 | 根因判断 |
|---|---|---|---|
| 1 | **对局部裁剪判断退化**：12/12 全答 "Yes" | I-29 | LVLM 对局部细节不敏感（AnomalyGPT 原文同样结论） |
| 2 | **绝对判断的数字是基率假象**：66.7% 恰等于异常占比 | I-29 | 训练数据单一 + 无交替训练 → 坍缩到常数回答 |
| 3 | **把 VLM 特征拼进密集解码器无效**：−0.005 | I-26 | 视觉塔的 patch 特征不是为密集预测训练的 |
| 4 | **语言/文本先验全部无效**：8 次实验 | I-17~I-21 | CLIP 只对齐了 CLS/EOS，patch token 从未被语言监督 |

**唯一站得住的正向结果**：VLM 的**整图相对比较**能力，79.25% [76.9, 81.5]（I-30，1,200 组，随机 50%）。

这决定了 v2 的设计取向：**让 VLM 做它擅长的（整图级语义裁决），把定位交给专门模块。**

## 3. 总体架构

```
                        ┌──────────────── 数据层 ────────────────┐
  真实数据（Real-IAD 图 + mask + defect_norm）
  模拟异常（cut-paste + Poisson，mask 免费、面积按真实分布采样）
                        └───────────────┬────────────────────────┘
                                        │ 指令化：判断 / 类型 / 位置 / 描述 / 推理链
                                        ▼
                        ┌──────── 视觉层（全部冻结）────────┐
       输入图 448–518 →│  DINOv3-L/16      32×32×1024 patch │
                        └───────┬──────────┬──────────┬──────┘
                                │          │          │
                    ①解码器 ────┘   ②图像锚点┘   ③projector
                    (~4M)            (~10M)        (44.8M)
                      │                 │             │
                  像素图 M         G_N / G_A     64 视觉 token
                      │                 │             │
                      ▼                 ▼             ▼
              Prompt Learner ──► 9 定位 token ──┐    │
                                                ▼    ▼
                        ┌──────── 语言层（VLM）────────┐
                        │ Qwen3-VL 的 LLM（8B, LoRA）  │◄── 指令文本 token
                        └───────────────┬──────────────┘
                                        ▼
                        文本输出：「有缺陷，是划痕，在左下角」+ 解释
                        辅助输出：像素图 M（来自①，非 LLM 生成）
```

## 4. 分模块详解

### 4.1 数据层

| 数据 | 规模 | 说明 |
|---|---|---|
| 真实异常 | 23,369 视角 | mask + `defect_norm`（20 类缺陷，100% 覆盖） |
| **模拟异常** | **1,080 张/折** | 已实现 `build_sim_anomaly.py` |
| 指令 | 5,000 条（当前）→ 目标 1.5 万 | 五类任务：判断/类型/3×3 位置/描述/推理链 |

**模拟异常的做法**（严格按 AnomalyGPT，并修了三个工程坑）：

1. **cut-paste**：从同类、**不同零件组**的正常图裁一小块；
2. **随机形状**：不是矩形，而是在补丁上再用随机 blob（椭圆/多边形/条带/不规则）裁一次；
3. **Poisson 融合**：`cv2.seamlessClone`，取回 mask 内像素（否则整图色彩会被拉灰）；
4. **贴在前景**：要求候选区域 ≥80% 是零件本体，避免贴到白背景上；
5. **面积对齐**：目标面积从真实缺陷分布采样（中位数 1.44%）。

实测：合成缺陷面积中位数 **1.39%**，真实 **1.44%**；面积档 small/medium/large = 497/314/269。

### 4.2 视觉层（DINOv3，全部冻结）

| 项 | 值 |
|---|---|
| 主干 | **DINOv3-L/16**（约 300M，冻结），patch 16 → 32×32×1024 |
| 为什么换 | Dual Anchors 的论证：DINOv3 视觉强、文本对齐弱；宁可要好的视觉特征，再用图像锚点补对齐 |
| 与 v1 对比 | v1 用的是 Qwen3-VL 自带视觉塔（576M），其 patch 特征不是为密集预测训练的 |

**三条支路**：

| 支路 | 模块 | 可训练 | 输出 | 作用 |
|---|---|---|---|---|
| ① 检测 | 轻量解码器（4 层融合 + focal/dice） | ~4M | 像素异常图 M | 像素级定位（v1 缺失的能力） |
| ② 图像锚点 | 层级分组 → 组 token G_N / G_A | ~10M | 2 个锚点 token | 补 DINOv3 的文本对齐弱（Dual Anchors） |
| ③ 对齐 | projector：1024→4096，8×8=64 token | 44.8M | 64 个视觉 token | 把视觉特征翻译进 LLM 词空间 |

### 4.3 语言层（**VLM 在这里**）

#### 位置

图中**红色框**：`Qwen3-VL 的语言模型`（`Qwen3VLTextModel`，8B）。

**它不在最前面**——前面是 DINOv3；也**不是整个 Qwen3-VL**——自带的视觉塔被弃用。

它位于**三条支路的汇合处**，只接收已经被翻译成 token 的证据。

#### 作用

| 负责 | 不负责 |
|---|---|
| **语义裁决**：有没有缺陷、是什么类型 | ❌ 像素级定位（①解码器的活） |
| **粗定位**：3×3 宫格方位 | ❌ 输出 mask |
| **生成解释**：为什么判异常 | ❌ 精确坐标 / bbox |
| **对话**：支持追问 | — |

> 依据：I-29 证明让 LLM 直接"看局部裁剪"会退化成恒答；I-30 证明它的强项是**整图级相对比较**（79.25%）。
> 所以 v2 让它看**已经处理好的证据**，而不是原始像素。

#### 输入 = 三类 token 拼接

```
[64 个视觉 token]  +  [9 个定位 token]  +  [指令文本 token]
      ↑                      ↑                    ↑
 DINOv3 patch           像素图 M 经            "有没有缺陷？
 经 projector(44.8M)    Prompt Learner         是什么？在哪？"
 → LLM 词空间 4096 维   (~10M) → 9 token
```

| token 类型 | 来源 | 数量 | 维度 |
|---|---|---|---|
| 视觉 token | DINOv3 32×32×1024 → 下采样 8×8 → projector | 64 | 4096 |
| 定位 token | 像素图 M → 5 层 CNN → reshape | 9 | 4096 |
| 文本 token | tokenizer(用户指令) | ~30–60 | 4096 |

同一条序列里，**位置编码按顺序拼接**，无需特殊处理。

#### 输出

- **文本**：`「有缺陷，是划痕，在左下角」`（判断 + 类型 + 3×3 方位 + 可选解释）
- **辅助像素图**：来自①解码器，**不是 LLM 生成的**

### 4.4 输出层

| 输出 | 来源 | 用途 |
|---|---|---|
| 判断（有/无） | LLM | 免阈值决策 |
| 缺陷类型（20 类） | LLM | 分类 |
| 3×3 方位 | LLM | 粗定位 |
| 自然语言解释 | LLM | 可解释性 / 报告 |
| 像素异常图 M | 解码器 | AUPRO 评测、精定位 |

## 5. VLM 速查卡

| 问题 | 答案 |
|---|---|
| **在哪** | 三条支路汇合处（图中红框），只保留 `Qwen3VLTextModel`（8B LLM） |
| **是什么** | 语义裁决器 + 解释生成器 + 对话接口 |
| **输入** | 64 视觉 token（DINOv3→projector）+ 9 定位 token（像素图→prompt learner）+ 指令文本 token |
| **输出** | 文本（判断 / 类型 / 3×3 位置 / 解释）；**不输出 mask** |
| **训练** | LoRA（r=16，q/k/v/o + gate/up/down），43.6M，占比 0.50% |
| **冻结** | DINOv3、LLM 主干（仅 LoRA 可训） |

## 6. 训练三阶段

| 阶段 | 做什么 | 可训练 | 产出 |
|---|---|---|---|
| **① 数据构造** | 真实 mask + defect_norm + 模拟异常 → 指令化（5 类任务） | 无 | `data/instructions_*.jsonl` |
| **② 模态对齐** | 冻结 DINOv3 + 冻结 LLM，只训 projector + 图像锚点 | 44.8M + ~10M | 对齐后的 projector |
| **③ 联合微调** | LoRA + projector + 解码器联合训练，**交替训练**（工业 : 通用 = 4:1） | 43.6M + 4M | 最终模型 |

**交替训练是防坍缩的关键**：I-29 里模型恒答 "Yes"，很可能就是只喂单一分布数据所致（AnomalyGPT 原作同样强调这一点）。

## 8. 与 v1 的对比

| 维度 | v1（已实现） | **v2（本设计）** |
|---|---|---|
| 视觉主干 | Qwen3-VL 视觉塔（576M） | **DINOv3-L/16（~300M，冻结）** |
| VLM 范围 | 整个模型 | **只用 LLM 部分** |
| LLM 输入 | 视觉塔产出 token | **视觉 token + 定位 token + 指令** |
| 像素定位 | 无 | **解码器输出，回灌为 9 token** |
| 训练 | 一步 LoRA SFT | **三阶段（数据→对齐→联合）** |
| 防遗忘 | 无 | **交替训练** |
| 数据 | 5,000 条真实指令 | **+ 1,080 张模拟异常** |

## 9. 支撑证据（本项目已完成的实验）

| 结论 | 节点 | 数字 |
|---|---|---|
| 冻结 DINOv2 跨类退化 | I-10/11 | 0.83（同类）→ 0.67（跨类） |
| 少样本参考最有效 | I-20 | 0.7616（B1）vs 0.7194（A0） |
| CLIP 文本先验无效 | I-17/19/21 | −0.004 / −0.017 / −0.21 |
| VLM 特征拼进解码器无效 | I-26 | −0.005（同条件对照） |
| VLM 绝对判断退化 | I-29 | 12/12 恒答 Yes |
| **VLM 整图二选一有效** | **I-30** | **79.25% [76.9, 81.5]** |

v2 的设计正是为了让每个模块只做它被验证过的部分。

## 10. 风险与判据

| 风险 | 判据 |
|---|---|
| 交替训练是否真的能防坍缩 | 若 SFT 后分类准确率 **不再等于异常占比**（即预测分布不再单一），说明有效 |
| DINOv3 是否值得换 | 先做 A0 换主干消融：fold0 AUPRO 是否 > 0.7194（配对 CI） |
| 定位 token 是否被 LLM 利用 | 消融：去掉 9 个定位 token，看位置题准确率掉多少 |
| 整体是否超过 v1 | 主指标：类型准确率（v1 = 12.8%，随机 25%）与二选一（v1 = 79.25%） |

**诚实预期**：v2 最可能改善的是**格式与判断的一致性**（不再恒答）和**类型准确率**；
像素级 AUPRO 的提升仍要靠 DINOv3 主干本身，别指望 LLM 贡献定位精度。
