# 跨零件异常分割：项目说明（唯一参考文档）

> 版本：v0.2（2026-10-21 定稿）

> 仅保留其结论（见《实验进度与版本记录.md》）。

## 1. 一句话

用 **DINOv2 提供密集视觉表征**、用 **VLM 提供语言接地的异常语义**，
证明「语言语义能弥补纯视觉模型在**没见过的零件类别**上的泛化缺陷」。

**主主张（可被证伪）**：

> 在整类留出（unseen category）协议下，把 VLM 的语义分支接到 DINOv2 分割模型上，
> 比同容量、同监督、同预算的纯 DINOv2 分割模型有更高的像素级 AUPRO；
> 且增益主要来自**语言**，而不是"多了一个视觉主干"。

**必须能反驳的三个替代解释**（对应 A1/A2 的对照）：

1. 涨了只是因为 VLM 的视觉主干更强 → 用 A1（只加 VLM 视觉）排除；
2. 涨了只是因为参数更多 → A0/A2 的解码器容量与训练预算完全对齐；
3. 涨了只是随机波动 → 四折均值±std + group 配对 bootstrap。

## 2. 任务定义

**输入**：一张工业零件图像（Real-IAD Variety 子集，5 视角拍摄中的单视角）。
**输出**：与原图同尺寸的异常概率图 `[0,1]^{H×W}`；阈值化后得到缺陷 mask。
**训练信号**：像素级 mask（二值），只在 **seen classes** 上使用。

三条边界（贯穿全项目）：

1. **只做分割/定位**，图像级分类只作为聚合诊断（`max(score)`），不作为主指标；
2. **测试类的标签与 mask 永不进入训练**（Protocol C 的 6 个 holdout 类整类扣除）；
3. 所有方法共用一个 split 文件、一套指标、一套阈值规则。

### 2.1 一个必须说清的事实

**DINOv2 不是分割模型**，它是自监督特征提取器（输出 patch 特征，没有 mask 头）。
所谓"DINOv2 的分割能力"= 冻结 DINOv2 特征 + 我们训练的解码器。
因此 A0 的强弱取决于解码器与训练，**不是 DINOv2 的固有属性**——这一点决定了
A0 必须调到一个有竞争力的水平，否则"加 VLM 更好"会被质疑为"基线没训好"。

### 2.2 第二个必须说清的事实

**Qwen3-VL 的视觉 token 与文本 token 不在对比学习空间里**（不像 CLIP）。
所以不能照搬 WinCLIP 的"patch ↔ 文本"余弦相似度；语言分支必须**在我们自己的
seen classes 上训练一个对齐桥**（projector / 文本条件头）。这正是 A2 的技术含量所在。

| 协议 | 文件 | 训练 / 验证 / 测试 | 回答的问题 | 在主表中的地位 |
|---|---|---|---|---|
| **A 原始分布** | `protocol_a_*` | 21,110 / 4,370 / 4,375 视角，24 类 | 同类别、新零件组；用来确认代码与指标没写错 | **不进主表**，只作 sanity |
| **B 同类新实例** | `protocol_b_*` | 20,950 / 4,515 / 4,390 视角，24 类 | 同一批零件类别里的**新零件**能不能分割 | 主表第一行 |

每折的 `holdout_classes.txt` 与 `sha256.json` 已冻结，`audit_report.json` 全绿。

## 5. 模型矩阵：每个实验在问什么

| 编号 | 视觉特征 | 语言分支 | 可训练 | 状态 | 回答的问题 |
|---|---|---|---|---|---|
| **A0** | DINOv2 多层 patch（冻结） | 无 | 解码器 | 代码就绪 | 纯视觉基线的跨类分割上限 |
| **A1** | DINOv2 + VLM 视觉塔 | 无 | 解码器 + 融合 | 未实现 | 涨的是不是"视觉主干更强" |
| **A2** | DINOv2 patch | **VLM/CLIP 文本锚点 + projector** | projector + 解码器 | 未实现 | **语言语义本身带来多少增益** |
| **A3** | DINOv2 + VLM 视觉 | VLM 文本 | 全部 | 未实现 | 两者叠加是否互补 |
| **A4** | = A3 | | + prompt adapter | 未实现 | 轻量任务适配（大模型能力） |
| **A5** | = A3 | | + q/v LoRA | 未实现 | 决策边界适配（大模型能力） |

### 5.1 A0：纯视觉基线（必须做强）

- 冻结 DINOv2-B/14，取第 3/6/9/12 层 patch 特征（去 CLS），各 768 维，reshape 成 32×32；
- 4 路特征 1×1 卷积到 256 后拼接 → 2 层卷积 → 1×1 输出 → 双线性上采样到 448；
- 损失 `0.5·focal(γ=2) + 0.5·dice`；
- 选档：val 宏平均 AUPRO@0.3；
- **判据**：A0 在 Protocol C 上若接近随机，先怀疑训练/评估，而不是急着加 VLM。

### 5.2 A2：语言分支（本项目的主张所在）

**代码状态：已实现（A2-a）**，`seg_cross_part/a2_language.py` + `train_seg.py --arm a2`。

```bash
# 随机锚点（= 随机锚点消融，也是本地/无权重冒烟）
python -m seg_cross_part.train_seg --protocol protocol_c_unseen_category --fold 0 \
  --backbone models/dinov2-base --arm a2 --text-encoder random --exp-id c_f0_a2rand

# CLIP 文本锚点（A2-a 主线）
python -m seg_cross_part.train_seg --protocol protocol_c_unseen_category --fold 0 \
  --backbone models/dinov2-base --arm a2 --text-encoder clip \
  --text-model models/clip-vit-large-patch14-336 --exp-id c_f0_a2clip

# 随机锚点消融的另一种做法：保留 CLIP 文本但打乱语义对应
... --text-encoder clip --shuffle-anchors --exp-id c_f0_a2shuf
```

产物比 A0 多一个 `anchors.pt`（锚点张量 + meta），离线复评直接读它重建语言分支。

三段式：

1. **文本锚点**：把一组"正常/异常"概念短语（可以比 WinCLIP 的模板丰富，VLM 能吃整句）
   编码成 K 个文本向量；
2. **对齐桥**：`P: R^{3072} → R^{d_text}`，用 seen classes 的 mask 监督训练；
3. **融合**：`s(patch) = cos(P(f), a_anom) − cos(P(f), a_norm)`，与 A0 的 decoder 输出逐点融合。

**必备消融**：把文本锚点随机打乱重跑一次。若打乱后不掉点，说明语言分支没起作用，
增益来自多出来的参数——这是最容易被审稿人抓住的地方。

### 5.3 A1：控制臂（为什么不能省）

如果只做 A0 vs A2，VLM 同时贡献了"视觉特征"和"语言"，无法归因。
A1 把 A2 的语言分支换成 VLM 视觉特征、其余完全一致，才能把两个因素拆开。

### 5.4 A4/A5：大模型能力（第二阶段，不能提前）

- **prompt adapter**：冻结视觉塔与 LLM，只训练 K 个虚拟 token + projector；
- **LoRA**：`q_proj/v_proj`，rank 8，alpha 16，dropout 0.05；
- 顺序不能反：先 prompt adapter 再 LoRA，否则分不清"缺任务接口"还是"决策边界要改"。

## 6. 训练链路

```
Dataset/<class>/<OK|NG>/...
      │  manifest.parquet（冻结）+ 协议 split（冻结）
      ▼
manifest_pixel.parquet（+mask_valid / area_bucket / defect_norm）
      ▼
SegDataset：图像 Resize/RRC 448 → ImageNet 归一化；mask 最近邻到 448
      ▼
A0：DINOv2(冻结) → 4 层 patch 特征 → SegDecoder → 448×448 logits
      ▼
loss = 0.5·focal(γ=2) + 0.5·dice
      ▼
每个 eval_step：val 上算宏平均 AUPRO@0.3 → 保存 best.pt
      ▼
val/test 全量推理 → 每类 PixelEvaluator → 宏平均 → metrics.json / frozen_protocol.json / results.csv
```

**固定配置（首轮，`seg_cross_part/protocols/seg_default.yaml`）**：

| 项 | 值 |
|---|---|
| 输入 | 448×448，ImageNet 归一化 |
| batch / eval_batch | 8 / 8 |
| lr / wd / warmup | 1e-3 / 1e-4 / 100 |
| 训练步数 | 6,000（评测点 1000…6000） |
| 选档 | val 宏平均 AUPRO@0.3 |
| 主干 | `models/dinov2-base`（冻结，不参与梯度） |

**为什么不用分类线的 8000 步 / batch 64**：分割要保存 448² 的 logits 与梯度，
显存与 IO 都更重；batch 8 是 24 GB 卡上的稳妥值。改动必须在版本记录里写明。

## 7. 评测标准 v1.0（2026-10-21 冻结）

> 这一节是**冻结条款**：出主表之前不许改。要改必须先改本节、写进版本记录、并重跑受影响的所有实验。

### 7.1 三个主指标 + 两个诊断

| 指标 | 定义 | 随机基线 | 用途 |
|---|---|---|---|
| **AUPRO@0.3** | 每区域重叠曲线在 FPR∈[0,0.3] 上的面积 ÷ 0.3 | **≈0.15** | **主指标**（对定位敏感） |
| **P-AUPR** | 池化像素的 PR 面积（每类先算再宏平均） | ≈ 像素阳性率（约 3%–6%） | **主指标** |
| **P-AUROC** | 池化像素的 ROC 面积 | 0.5 | **主指标** |
| I-AUROC | 图像分数（概率图 max）的 ROC | 0.5 | 诊断 |
| I-AUPR | 同上，PR | ≈78%（图像级阳性率） | 诊断 |

另外报 `P-F1max`（池化像素最优 F1，**oracle 阈值，只作参考**）与 `aupr_minus_prevalence`。

### 7.2 计算口径（逐条对齐，缺一不可）

1. **类内宏平均**：每个类先算自己的指标，再对 24（或 6）个类取平均。
   不是把全数据集像素混在一起算——跨类泛化要的是"每类都不掉队"。
2. **池化像素的抽样必须与标签无关**。超预算时对整张图按统一比例抽样
   （正负像素同比例），保持阳性率不变。
   > 为什么：AUPR 对阳性率敏感。若"保留全部正样本 + 只抽 2 万负样本"，
   > 阳性率会从 5% 被抬到 30%，AUPR 会虚高 0.3–0.5，完全不可比。
   > AUROC 不受影响，但 AUPR 会。
3. **AUPRO 的 FPR 必须用全部被评测图像**（含正常图）的误报像素数 ÷ 正常像素总数。
   > 只统计缺陷图内部的误报，会漏掉"模型在正常图上乱亮"的惩罚，AUPRO 虚高。
4. **AUPRO 的阈值网格固定为 256 个等距阈值**（对 sigmoid 概率切），跨图可比；
   曲线插值到 101 个 FPR 点后积分；端点补 (0,0) 与 (1,1)。
5. **正常图贡献 FPR，不贡献 PRO**；无缺陷区域的图不参与 PRO 平均。
6. **盲 NG 视角按视角级正常处理**（GT 全 0），不是错误、也不是忽略。
7. **阈值**：AUROC/AUPR/AUPRO 与阈值无关，永远报；若报二值指标（P-F1/P-Recall），
   阈值必须在 val 上冻结后套到 test，并注明 "at val-frozen threshold"。
8. **显著性**：以 `group_path` 为单位做配对 bootstrap（1,000 次，95% CI），
   重采样单位是零件组，不是图。

### 7.3 为什么这么定（三个已经踩过的坑）

| 坑 | 后果 | 现在的做法 |
|---|---|---|
| 负样本下采样 | P-AUPR 虚高（5% → 33% 阳性率） | 标签无关均匀抽样 |
| AUPRO 只算缺陷图的 FPR | 漏罚正常图误报，AUPRO 虚高 | FPR 用全部图像 |
| 用 F1@τ 当主指标 | 78% 阳性率下阈值滑向"全判异常"，实测 FPR@τ=1.0 | 主指标全部阈值无关 |

### 7.4 与文献的对应（写论文时必须交代）

- MVTec / Real-IAD 常用：I-AUROC、P-AUROC、P-AUPR、PRO@0.3 —— 我们都有；
- 我们额外报**类宏平均**与**四折均值±std**，因为研究问题是跨类泛化，不是同分布精度；
- 我们**不报**"只在大缺陷上"的筛选结果作为主表，只作分层分析。

### 7.6 分层与置信区间（已实现）

训练时只留聚合指标，事后无法分层、也无法重采样；因此另设一条**离线评测链路**：

```bash
# 1) 从 checkpoint 复评，落盘每图统计量
python -m seg_cross_part.evaluate_pixel --run artifacts/seg_cross_part/<exp_id> --split test

# 2) 单模型 95% CI；或两模型配对差值 CI
python -m seg_cross_part.bootstrap_pixel --stats <exp>/stats_test.npz --n-boot 1000
python -m seg_cross_part.bootstrap_pixel --stats a0/stats_test.npz a2/stats_test.npz --names A0 A2
```

- `evaluate_pixel` 每张图只保存 **256 桶正/负像素直方图 + 每区域覆盖曲线**（约 6 KB/图），
  以及 group / 类别 / 面积档 / 图像分数；同时输出 `overall`、`by_class`、`by_area`；
- `bootstrap_pixel` 以 **group_path** 为重采样单位（1,000 次，95% CI）；
  两模型用**同一批重采样**算配对差值，并给出 `P(Δ≤0)`；
- 直方图口径与逐像素口径的偏差已验证 **≤0.004**（AUROC/AUPR/AUPRO），
  1000 次 bootstrap 约 11 秒/模型。

### 7.5 不允许的操作

1. 只报四折里最好的一折；
2. 用 test 选阈值、选 checkpoint、选超参；
3. 发现哪个指标不好看就换指标口径；
4. 把 oracle 阈值的 F1 与 val 冻结阈值的 F1 混在一张表里。

## 8. 纪律红线

1. **holdout 类永不参与**训练、阈值、配比、超参、early-stop；
2. **test 错误不回流训练**；
3. **一次只改一个因素**，并在版本记录里写明"相对于上一行改了什么、预期是什么"；
4. 所有 run 必须留 `frozen_protocol.json`（含 split sha256、配置、指标）；
5. 负结果照实记录，不为了让曲线好看而换指标。

## 11. 开跑前复核（强制）

**为什么**：曾经因为 `--protocol` 只改了名字、配置文件仍是 B，白跑了三个 34 分钟的 fold。
所以复核不是"建议"，而是**代码里的关卡**：`train_seg` 默认先跑 `preflight`，任何一项 FAIL 就拒绝训练。

### 11.1 两种用法

```bash
# 手动单跑（推荐：开跑前先看一眼）
python -m seg_cross_part.preflight --protocol protocol_c_unseen_category --fold 0

# 自动：train_seg 默认先复核，通过才训练
python -m seg_cross_part.train_seg --protocol protocol_c_unseen_category --fold 0 ...
```

确需跳过：`--skip-preflight`，并在《实验进度与版本记录》里写明理由。

### 11.2 检查项（17 项）

| # | 检查 | 判定 |
|---|---|---|
| 1 | 配置文件存在 | 必须是 `protocols/<name>.yaml` |
| 2 | 协议名与 type 一致 | 名字含 `unseen` 但 `type≠c` → FAIL |
| 3 | fold 合法性 | C 必须给 fold；非 C 不许给 |
| 4 | 类别交集 | C 必须为 0；B/A 必须全交 |
| 5 | train/test 视图数 | 与冻结值比对，偏差 >5% → FAIL |
| 6 | 类别数 | C: 18/6；B: 24/24 |
| 7 | manifest_pixel 覆盖 | train/val/test 的 image_path 必须全在 |
| 8 | 元信息完整 | group_path / area_bucket 无空值 |
| 9 | 抽样图像可读（20 张） | 缺失 → FAIL |
| 10 | 抽样 mask 可读（20 张） | 缺失 → FAIL |
| 11 | 图像/mask 几何对齐 | IoU 自检 <0.90 → FAIL |
| 11b | 指标口径自洽 | `PixelEvaluator` 与 `PixelStats` 对同一批数据 Δ>1e-6 → FAIL |
| 12 | 输出目录冲突 | 已存在且非空 → FAIL（除非 `--overwrite`） |
| 13 | 设备 | cuda / mps / cpu + 显存 |

### 11.3 通过时的样子

```
[protocol] type=c fold=0 | train 18 类 / test 6 类 | 类别交集 0 | train 17890 视图 / test 7455 视图
[PASS] test 视图数 — 7455（期望 7455±5%）
...
复核结论：17/17 项通过 → 可以开跑
```

### 11.4 失败时的样子（真实案例）

```
[FAIL] 协议名与 type 一致 — name=protocol_c_unseen_category type=b
[FAIL] 协议/类别校验 — 协议名 protocol_c_unseen_category 表示「未见类别」，但配置 type=b。
复核结论：15/17 项通过 → 禁止开跑
```

**看训练日志的第一行**：`type=c`、`类别交集 0`、`test 7455 视图`。三者缺一，立刻停。
