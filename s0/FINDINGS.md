# S0 关键数据质量调查：S 号、视觉近重复与拆分单位

## 实测证据

以下距离均基于 C1 视角的 64×64 灰度缩略图 MSE（×1000 标度）。

1. 同 S 跨批有时很近：`ceramic_fuse` 的 OK/S0001 与
   NG/BrokenWire/S0001 为 9–17；但同类 OK 与 NG/Damage 的同 S 可达 918。
2. 五类系统抽样中，“同 S 跨批”距离中位数 76，“不同 S 同批”反而是 29。
   因而 S 号不能作为跨批物理身份键。
3. OK→NG 最近邻很近的比例因类而异：`ceramic_fuse`、`3_adapter` 约 100%，
   `blade_switch` 约 90%，`detection_switch` 约 50%。数据里确实存在跨批视觉
   近重复，但仅凭图片不能证明它们一定是同一个物理实体。
4. 全局 C1 阈值图对阈值敏感：阈值 8 得到约 3931 组，阈值 30 约 965 组。
   内容聚类不能提供无噪声、唯一的“真实物理零件数”。

## 对旧结论的纠正

旧记录曾写“把同一工件拆成多个簇（更多簇）不会泄漏”。这是反的：如果这些簇被
分别抽进 train 与 dev，恰好会造成泄漏。防泄漏的安全方向应是：

- 已发现近重复关系的样本必须原子化地进入同一个集合；
- 宁可把若干不同但相似的工件合成更大的组（dev 变少），也不能把近重复链拆开；
- 无约束单链会产生 chaining，已弃用。当前只连接“跨采集批、互为最近邻、距离
  低于阈值”的 C1，并强制每个分量同一批最多一个成员。即使如此，产物仍只能叫
  `visual_group_id`，不能夸大为真实物理 ID。

## 固定契约

- `group_path`：一次 5 视角拍摄，始终是图像级评测样本。
- `source_part_key=<类>/<Sxxxx>`：只用于追溯源数据，不用于防泄漏或评测聚合。
- `visual_group_id`：C1 阈值图的连通分量，只用于 train/dev 原子化拆分。
- `holdout-zs`：仍按整类扣出，已经写出的四折类别表默认冻结，不能因修复 dev
  拆分而重新抽签。

## 不可避免的限制

若某类在完整视觉组约束下无法同时给 train/dev 留出足量 OK 与 NG，拆分脚本必须
将该类明确标为 `dev-unsplittable`，而不是退回按 S 号强拆。阈值选择及该限制需
随实验结果一起报告。
