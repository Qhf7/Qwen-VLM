# D联合适配与排序目标：完成结果的技术解读

日期：2026-11-04。分析基于本地汇总、原始预测复算标记和独立检查记录；未查询服务器/GPU或读取外部新结果。D、Cpair、R各42/43/44共9次正式500步运行完成，18份best/final预测报告（6840行）复算一致。9个新进程分别加载基座与源桥接，对best和final各28张原验证样本保持原batch伙伴重验；分数零误差、生成精确一致、关闭adapter参考一致。该验证证明保存/重建一致性，不能替代独立评测。

## 1. 当前证据最支持什么

1. 固定视觉前端后，语言适配继续有可测量价值：历史C比原始Qwen桥接起点改善，D在相同采样和新增预算下比C有较小但三seed一致的AUROC/AP与生成F1增量。
2. 对语言首答案分数加入同类别正负排序目标，确实改变了异常排序和决策行为。R比严格匹配的Cpair三seed AUROC/AP均升，平均生成召回升，但误报同步上升，且生成F1只有2/3seed升。
3. 现有结果支持“参数高效领域适配与目标对齐”，不支持“复杂推理增强”或“已验证跨数据集泛化”。答案目前主要是固定Yes/No；结构化位置与真实工具调度仍在后续阶段。

## 2. D比C：接口与语言共同更新的增量

D与历史C都从各自seed的原始phase1桥接起点出发；不是在训练完成的C adapter上再继续。相同500次更新、microbatch1×accum4、2000曝光和相同采样序列。C只训练语言q/v LoRA 3,833,856参数；D再让111,614,904参数桥接以1e-5更新，LoRA仍为1e-4，总115,448,760参数。

best AUROC增量+0.3275±0.1783pp；固定final500也为+0.3466pp，说明增量不只出现在best选择结果。但两者仍在同一开发集上评价，三seed本身不是独立样本泛化验证，也不足以机械宣称统计显著。

## 3. 排序实验必须对Cpair，而不是直接对历史C

R与Cpair均冻结桥接、训练同样的q/v LoRA，从相同seed源桥接/零初始化adapter出发，新增500更新/2000曝光。二者采用同类别normal/anomaly配对、类别等概率有放回采样、microbatch2×accum2；CE在同一两图微批次上按全部监督token取均值，然后按累积归约。R唯一新增项为：

    L = L_CE + lambda * softplus(-(s_anomaly - s_normal))
    s = logit(Yes) - logit(No)

logit来自训练forward，保留梯度；没有调用no_grad评测score来充当训练目标。lambda通过16对训练样本的初始梯度范数比值中位数14.06366，按预定[0.01,1.0]截断得到1.0；只做train-only尺度标定，没有用val/MVTec调lambda，也不意味着lambda1.0最优。

历史C是不同采样与microbatch1×accum4；CE每图归约再平均也与双图token-mean不同。R减历史C会混入采样、微批次与CE归约差异，不能把全部差值归给ranking。Cpair vs C可以作为配方变化的完整比较，不能用于单独证明排序机制。

## 5. 为什么AUROC上升仍可能有更多误报

AUROC评价跨阈值排序；排序损失直接推动同类别异常分数高于正常分数。它没有单独约束所有正常分数必须低于0，也不校准真实概率。即使正负顺序更好，固定阈值附近或实际生成的Yes/No行为仍可能变得更积极。

当前score决策规则为s>0，生成指标来自真实greedy答案的首个Yes/No；二者分开报告，不能默认每张图都相同。阈值校准作用于分数分类器，不会自动改变原始生成回答。若部署采用分数阈值控制最终决策，还需明确生成文本与阈值冲突时的输出契约，避免显示No解释却发出Yes告警。

后续可以另建预注册阈值实验：只在VisA开发/独立校准数据选择满足目标FPR或业务代价的阈值，锁定阈值后再评价新的留出数据，报告Recall@FPR、precision与成本曲线。当前val已经用于多轮选型，校准后的该val成绩仍属于开发结果；不得用冻结的MVTec外评结果反向改阈值。此提议不修改本轮protocol、score阈值0、checkpoint选择或生成规则，原始结果完整保留。
