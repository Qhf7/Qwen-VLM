# B0+ 两个 Qwen-VL 版本差距分析（smoke20 → 36 完整样本扩展）

## 结论先行

这不是“Qwen3 的视觉能力整体比 Qwen2.5 差一大截”的证据。两次测试中两个模型的硬准确率都接近随机（样本级 50%），但 next-token 分数的基线完全不同：Qwen2.5 几乎总是偏向 `No`，Qwen3 几乎总是偏向 `Yes`。因此差异主要表现为**答案先验/校准和排序稳定性**，而不是同等阈值下的能力差距。

## 扩展测试

固定 fold1 Dev 中按 18 类各取 1 个 OK 与 1 个 NG，得到 36 个完整样本、180 个视角；两模型均使用 direct resize 448、同一 P0 英文提示、同一 5-view max 聚合、float16/MPS。

| 指标 | Qwen2.5-VL-3B | Qwen3-VL-2B |
|---|---:|---:|
| 样本级 I-AUROC | 0.7454 | 0.5401 |
| 样本级 I-AUPR | 0.7913 | 0.5670 |
| F1max | 0.7442 | 0.6667 |
| 18 类宏 AUROC（脚本当前报告口径） | 0.8333 | 0.5556 |
| 视角 accuracy@0.5 | 51.11% | 48.89% |
| 样本 accuracy@0.5 | 50.00% | 50.00% |
| OK/NG 的 P(Yes) 中位数 | 0.2045 / 0.2365 | 1.0000 / 1.0000 |
| 首词解析、JSON 合法率 | 100% / 100% | 100% / 100% |
| 5-view warm p50 | 11.66 s | 6.08 s |

按 36 个样本做简单 bootstrap（2000 次）时，Qwen2.5 的 AUROC 95% 区间约为 [0.574, 0.898]，Qwen3 约为 [0.341, 0.723]；区间很宽，说明仍不能把这次扩展当成最终结论，但 Qwen3 的饱和现象已不是 smoke20 中单个样本造成的。

## 为什么会出现这么大的数值差距

1. **答案先验饱和。** Qwen3 的 `P(Yes)` 在 180 个视角几乎全部为 1，并生成 `Yes {"region":"center"}`；Qwen2.5 几乎全部生成 `No {"region":"none"}`。在 0.5 阈值下两者都约 50%，但连续分数的排序完全不同，所以 AUROC/AUPR 会被显著拉开。
2. **这两个 checkpoint 不是参数可比的“同一模型小版本”。** Qwen2.5 为 3.75B 参数、448 输入对应约 32×32 视觉网格；Qwen3 为 2.13B、约 28×28 网格。视觉 patch 数、投影层、指令微调和输出校准都改变了；“版本更新”不保证在工业缺陷二分类 prompt 上保持同一输出尺度。
3. **任务形式与训练分布不匹配。** 我们要求模型把自然语言回答的第一个 token 强制当作分类器，再继续输出 JSON。这不是两个模型原生的分类头；聊天模型会根据指令微调形成强烈的 Yes/No 语言先验，且该先验可能覆盖细微缺陷证据。
4. **区域输出不是独立证据。** Qwen3 的 `center` 是明显位置先验，Qwen2.5 的 `none` 是正常图先验；区域准确率分别 31.82% 和 0%，只能说明输出契约/位置先验，不等价于缺陷定位能力。
5. **样本量仍小且视角高度相关。** 36 个样本不是 180 个独立样本；同一物体的 5 个视角共享外观。单个 group 的 max 会放大偶然高分，因此必须以 group 为 bootstrap 单位，并在 720 Dev-mini 上确认。

## 已排除与仍需控制的协议风险

- 已核验两套 tokenizer：`Yes`、` Yes`、`No`、` No` 的候选 ID 在本地两模型中一致（分别为 9454/7414 和 2753/2308），所以本次差距不是错误复用 token ID。
- 仍应在正式比较中保存并比对两模型序列化后的 chat-template、视觉 token 数和首 token logits；Qwen3 的模板/推理开关与 Qwen2.5 不应假定等价。
- 结论应优先报告 `yes_logit-no_logit`、原始 P(Yes)、硬准确率和校准曲线，不只报告单一 AUROC。

## 对 B0+ 主线的处理建议

冻结的 Qwen2.5-VL-3B + P0 + direct448 + B0f 仍作为主线；本次 Qwen3 结果作为对照，不替换主线。下一步先在同一 720 Dev-mini 上一次前向保存两模型的逐视角 logits，再离线计算 max/top-2 mean/mean、18 类宏平均和 group bootstrap 区间；如需公平比较阈值，另设独立 calibration split 做温度/阈值校准，不能在评测集上调阈值。只有在协议核对和大样本校准后，才判断是否存在真实视觉能力差距；在此之前不要开启 Visual Adapter 或 LoRA。
