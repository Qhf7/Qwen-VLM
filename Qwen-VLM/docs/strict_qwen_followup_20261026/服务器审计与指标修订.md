# 服务器快照审计与指标修订

> 本文保留早期静态审计过程。后续 GPU 已完成四层平均图修订；当前 v2 的图像标签使用显式标签／Yes-No 语义，像素 GT 保留 mask >0.3。两个语义阳性的 soft mask 在该阈值下为空，不能仅据此判定合成失败。主流水线及诊断现已完成，最新数字见[最终实验结论](最终实验结论.md)和重建后的结果报告。

日期：2026-10-26。依据是主任务已归档到 `AnomalyGPT/followup_20261026/server_snapshot/` 的真实服务器文件；本审查没有另行连接服务器，也没有更改旧代码或结果。下面区分已确认的实现事实与等待 GPU 重算的数字。

## 像素指标应改为最终异常图的指标

`code/cached_train_strict.py:32–40` 和 LoRA 版本将四个 decoder 层分别变成两类 softmax 概率图，再对异常类概率取四层平均。这个平均图才被送入 Prompt Learner。

但 `code/eval_cached_strict.py:42–55` 及 `eval_cached_strict_lora.py` 对各层 map 分别追加到列表，最终沿样本维 concatenate，并同时重复 GT。它们测量的是“四层输出合并池化”的像素排序，而非“最终四层平均异常图”的排序。每个 variant 实际贡献了四份预测，历史输出仍把 `num_variants` 写成缓存文件数。

因此此前 Pixel AUROC/AP 数字不能继续标作最终异常图的成绩，必须重算初始化、冻结 Qwen 三 seed 和 LoRA 三 seed。旧文件应保留并注明历史计算定义；不能推测重算后差值方向或沿用“定位没有改善”的数字结论。

新增 [corrected_synthetic_eval.py](../../AnomalyGPT/followup_20261026/corrected_synthetic_eval.py) 只实例化原 `AnomalyGPT_models.py` 中的 `LinearLayer(1280,1024,4)`，严格加载 checkpoint 中的八个 `image_decoder` 参数。使用 BF16、100 倍余弦相似度、224 双线性插值（`align_corners=True`）、每层 softmax 后平均。它不会加载 Qwen、ImageBind、Prompt Learner 或 LoRA，因为这些模块不参与缓存后的 map 计算。

输出包括 pooled、逐类别与类别宏平均 Pixel AUROC/AP、Image AUROC/AP。图像分数为最终 map 的最大值；图像 GT 由实际 mask 决定。每个类别指标不可定义时输出 `null`，宏平均同时记录参与平均的类别数，避免静默填零。

```bash
python corrected_synthetic_eval.py \
  --cache /absolute/path/to/cache_balanced_test24 \
  --checkpoint /absolute/path/to/runs/balanced_strict_16/pytorch_model.pt \
  --initial-checkpoint /absolute/path/to/ckpt/train_visa/pytorch_model.pt \
  --model-source /absolute/path/to/code/model/AnomalyGPT_models.py \
  --out /absolute/path/to/corrected/balanced_strict_16.json
```

初始化基线省略 `--checkpoint`，此时只加载 `--initial-checkpoint`。LoRA 分支使用该分支的 bridge `pytorch_model.pt`；像素 map 不依赖 LoRA adapter 的推理，但 decoder 权重可能已受联合训练梯度影响。

## variant=1 不保证真的含异常

`code/datasets/visa.py` 在 `patch_ex` 没有生成中心点时，将所谓 abnormal conversation 设成正常回答。缓存脚本仍把该记录保存为 `variant=1`。因此 `48 variant = 24 normal + 24 abnormal` 不能仅凭文件后缀推断。

修订脚本逐条报告 `variant`、实际 mask 阳性像素数、文本 Yes/No 标签及其一致性；统计 `variant1_empty_mask_files`。像素 GT 延续旧训练与评价的 `mask > 0.3` 定义。若文本说异常、mask 在该阈值下为空，会作为实际不一致列出，不能静默排除。最终指标包含所有缓存记录。

已归档 manifest 证明训练缓存为 96 条记录、48 个来源；测试为 48 条、24 个来源。实际有缺陷的 variant 数量要以 tensor mask 审计输出为准。

## token accuracy 没有发现因果标签错位，但需要改汇总口径

`openllama_qwen3vl_strict.py:481–484` 的 CE 对齐为：

```python
logits[:, :-1]  vs  targets[:, 1:]
```

旧 accuracy 对齐为：

```python
logits[:, 1:-1]  vs  targets[:, 2:]
```

后者只额外移除了第一对“位置 0 预测位置 1”。`prompt_wrap` 把 BOS、图像和软提示前缀标签全部设为 `-100`，所以 `targets[:,1]` 已被忽略；当前有效监督 token 集合与标准 causal shift 相同。不能据此指控模型在预测当前位置，或把历史高 token accuracy 解释成标签错位。一个带前缀 mask 的人工张量 fixture 已验证两种切片在有效 token 数与正确 token 数上等价。

实际汇总问题在旧 evaluator：它先得到每批 `correct/valid`，再按该批图片数加权平均；这不等于全测试集 `sum(correct)/sum(valid)`，尤其正常／异常回答长度不同。新语言评测应统一使用标准 shift，保存分子、分母，并汇总全部监督 token。历史字段已命名为 `mean_batch_token_acc`，只能按该口径保留。

无论采用哪种汇总，teacher-forcing token accuracy 都不能替代自由生成答案的异常判断准确率。真实 VisA 评测仍需单独报告完整生成答案的 Macro-F1、异常召回、正常误报率和无法解析比例。

## 初始化元数据已变得可核验

新归档的各 `runs/*/run.json` 明确显示，冻结和 LoRA 三 seed 的 `init_ckpt` 都是 `../ckpt/train_visa/pytorch_model.pt`。这比此前只有会话摘要的状态更完整；但还须把该路径解析为真实绝对文件、核对 SHA256 与来源，并审计发布权重的训练信息权限。当前 source split 的隔离只约束新增训练阶段，不能自动证明初始权重从未见过任何测试来源。

## 本轮验证与待完成项

修订脚本已在 CPU BF16 临时 fixture 上跑通：三条缓存只产生三张最终 map；空 mask 的 `variant=1` 被正确计为正常，文本／mask 一致性被记录；pooled、per-class、macro 及 checkpoint hash 正常输出。这个 fixture 验证数据流与统计口径，不是新模型性能结果。

真实服务器缓存和 checkpoint 的 GPU 重算结果由主任务另外落盘。未获得这些输出前，本报告不填入任何修订后的性能数字，也不以旧 Pixel AUROC/AP 差值决定是否扩训。
